# Agent 有了记忆，怎样才会越做越好？

记住一段经历、从经历中总结办法、在新任务中用对办法，是三件不同的事。今天主读 LifeMem：把跨环境轨迹按做事步骤分组，再提炼可复用技能。AdaMEM 关注任务执行到一半时怎样根据新情况更新策略；MemoryArena 检查记忆能否帮助完成依赖过去结果的后续任务。三篇一起区分外部记忆的积累、当前上下文的适应与离线权重训练。先读主读的具体例子和流程，有兴趣再比较两篇选读，不需要一天读完。

每天推荐 1 篇主读与 2–4 篇选读，覆盖 LLM Inference、RL Infra、Post-Training、RSI（递归自我改进），以及推理计算、Agent 学习与记忆、数据评估和模型架构。经典与前沿并行，按主题逐步展开；不要求与当前工作直接相关。候选不等于已读，无需一天读完。

## 主读 · LifeMem: Enabling Lifelong Experience Reuse for LLM Agents

**年份 / 发表信息：** 2026 · arXiv 2026 · BIT / Beihang / HIT / Baidu · v1 2026-09-11 · [原文](<https://arxiv.org/abs/2609.12655v1>)

**阅读建议：** 值得精读机制与消融。先看 Figure 2 和 §4，再读 Table 3/9 判断轨迹与技能各自贡献，最后看任务顺序、FEVER 迁移及逐数据集结果。论文的平均改善有意义，但不支持所有环境都更好或已经实现无限期自我改进。

### 为什么查过很多资料，下一次反而可能用错工具？

假设一个 agent 曾通过维基搜索查出某座博物馆的开馆年份，也曾调用数据库工具查询价格。今天它要核验“这座博物馆于某年开放”这个说法。以下是教学例子：如果记忆系统只按文字相似度找旧记录，可能取出主题相近、操作接口却不同的轨迹。模型学到了旧示例的调用格式，当前工具却根本不接受它。

一条轨迹就是一次任务中的观察与动作记录：看到了什么、调用了什么、工具返回了什么。原样保存轨迹能留下具体经验，但它也绑定着当时的环境。反过来，只留下“先分析，再行动”这类宽泛总结，又不足以指导下一步。LifeMem 试图同时保留可照着操作的细节，以及跨任务仍有用的步骤原则。

论文附录确有类似失败：核验事实时，基线检索到另一工具环境的记录，随后写出带错误外层括号的搜索动作。LifeMem 在这个例子里取同属维基搜索环境的记录，避免格式误导。这个案例说明干扰怎样发生；平均效果还需要后面的实验判断。[论文 v1 与 Appendix N](https://arxiv.org/html/2609.12655v1#A14)

### 这里“学到经验”改变的是记忆库，不是模型权重

LifeMem 让语言模型执行任务，同时把积累的经验放在外部记忆中。下一次执行前，把相关记忆作为文字加入输入，模型据此选动作。论文方法没有通过这些经验做梯度更新；它改变的是轨迹、分组说明和技能文本。这里的学习属于非参数记忆学习，即经验保存在模型参数之外。

这一区分也改变了“遗忘”的含义。即使模型权重未被新训练覆盖，旧任务的表现仍可能下降：检索到不合适的记录，摘要被后来经验改得太泛，或多份建议互相干扰，都可能使旧经验难以使用。因此不能把本文减少遗忘的结果，直接当成解决神经网络参数灾难性遗忘的证据。

本文依据 Yuli Qiu 等人的 2026 年 9 月 11 日 v1，团队来自北京理工大学、北航、哈工大与百度，论文采用 CC BY 4.0；本篇为解释与评议。作者标注已被 EMNLP 2026 主会接收，本次尚无会议方独立确认；下文讨论的是原论文中可核对的方法与结果。[论文与许可](https://arxiv.org/abs/2609.12655v1)

### 写入第一步：先判断这次经历属于哪一种工作流程

LifeMem 用五条初始轨迹建立记忆。语言模型按完成任务所需的共同步骤把它们分组，每组称为一个工作流簇，并生成简短说明。工作流强调“为了得到结果，需要依次解决哪些子问题”，不只看任务里是否出现相同名词。前面的教学例子中，“定位实体—消除歧义—查找属性—核对证据”就比“关于博物馆”更像可复用流程。

每来一条新轨迹，系统先用向量检索找四条相关旧轨迹，拿到它们所在簇的说明，再让语言模型判断：新经验能否加入其中一个簇？如果可以，就加入并更新说明；如果不合适，就新建簇。向量检索把文本转换成便于比较的数值表示，负责缩小候选范围；最终分组还经过语言模型判断。

论文用 all-MiniLM-L6-v2 生成向量、FAISS 检索、SQLite 保存分组；GPT-5-mini 负责新轨迹分配，GPT-4.1 负责后续拆分与技能提炼。这是论文当时的配置，不是当前产品选择建议。它也表明系统需要多次模型调用来整理经验，并非把文本放进数据库就自动完成学习。[§4.1–4.2 与 §5.4](https://arxiv.org/html/2609.12655v1#S4)

### 一组经验变得太杂时，怎样拆开并提炼技能？

一个簇越装越多，原来的说明可能不再准确。但重复相似任务导致的“大”，与混入不同流程导致的“杂”，不应一律处理。论文先把簇内每条轨迹的向量缩放到长度为一，再求平均，检查平均向量的长度 R。方向接近时 R 接近一，方向分散时它变小。

这个量叫 mean resultant length，简称 MRL。§5.4 所列规则是同时满足“轨迹数超过 50”与“R 小于 0.95”才触发拆分。它是一个决定何时请求语言模型重新分组的信号。需要注意，向量方向一致不等于工作流程必然一致；MRL 是所选 embedding 下的近似判断，不能数学上保证聚类正确。

分组后，系统从簇里的成功轨迹提炼三至五条通用规则。例如教学示例可以总结为：“先确认目标实体；有同名结果时先消歧；答案依赖多个属性时分别查询并交叉核对。”这些就是本文的 skills：可读的文字建议，而非可执行函数，也不是新训练出的神经网络模块。它们在相对一致的簇内产生，意在减少无关经验混入摘要。[§4.2、Appendix L](https://arxiv.org/html/2609.12655v1#S4.SS2)

### 读取时，两类记忆分别回答两个问题

执行新任务时，第一层记忆提供同一环境的历史轨迹，回答“这里的工具具体怎样调用”。例如仍使用维基搜索工具时，示例里的 Search、Lookup 和 Finish 格式可以继续参考；不能把数据库接口的语法照搬过来。论文将这类示例称为 environment-aligned trajectories，即与当前环境匹配的轨迹。

第二层取得这些轨迹所属簇的技能，回答“完成这类任务通常需要哪些步骤”。一个簇可以包含不同环境里具有相似流程的经历，因此文字技能能带来其他环境的经验，而不用把其他环境的低层调用格式一起塞给模型。最终输入同时包含题目、当前观察、具体示例和抽象规则。[§4.3](https://arxiv.org/html/2609.12655v1#S4.SS3)

回到博物馆例子：旧问答任务与新的事实核验任务，最终输出要求不同，但都需要查实体和核对证据。已有维基轨迹帮助模型正确调用工具，技能帮助它规划查证步骤。这个解释说明了两层设计为何可能互补；它不意味着所有跨环境流程都能自动迁移，更不能把抽象建议当作当前环境规则的替代品。

### 实验经历了多长的学习过程，经验是谁提供的？

Table 1 列出十个环境的 12,489 条训练实例和 1,230 条测试实例，覆盖具身操作、工具使用、搜索、数据分析与浏览器操作。主实验按环境分阶段加入经验，再回头评估已经经过的任务。LifelongAgentBench 只提供训练数据，因此最终总体分数实际平均了九个测试数据集。这里的“超过一万三千任务”包含训练与测试，不能说成 agent 在线独立完成了这么多任务。

其中四个数据来源由作者补建：GPT-4.1 在环境中生成 2,310 条轨迹，环境反馈判断 1,541 条成功。五位人工评审检查中间步骤是否合理，报告超过 90% 的步骤合理。这个比例不是完整任务成功率，也不是人工从头写了两千多条解法。教师生成、环境反馈、人工检查和记忆整理共同构成了经验来源。[§5.1 与 Appendix B](https://arxiv.org/html/2609.12655v1#S5.SS1)

执行任务的模型是 GPT-4o-mini、Deepseek-v3.2-exp 和 Qwen3-32b；采样温度为 0.3，后两者不开启 reasoning 模式。经验抽取基线同样使用 GPT-4.1，以减少抽取模型选择造成的差异。实验支持的是这段有限、预先构建的数据流中的积累与复用，尚不是一个自主探索、自己修改学习算法并无限改进的闭环。

### 读成绩表时，要把最后的水平与旧任务的变化分开

Overall Performance，简称 OP，是全部经验加入后，在各测试数据集上的分数再取平均。GPT-4o-mini 的 LifeMem 得到 44.13，无记忆 ReAct 为 28.84，最强的记忆基线 ExpeL 为 41.85。与后者相比是增加 2.28 个分数点，约 5.45% 的相对改善；不能把论文写的 5.45% 当成增加 5.45 个百分点。

Backward Transfer，简称 BwT，问的是另一件事：加入后来的经验后，早先任务相对刚学完时提高或下降了多少？教学例子：某任务从 50 分变为 55 分，增加五分，但相对变化是 `(55−50)/50 = 10%`。论文先对各旧任务算这种相对变化，再取平均；最后一个任务没有后续阶段，因此不参与这个指标。

LifeMem 在三个执行模型上的平均 BwT 均为正，GPT-4o-mini 为 +5.66%。这不代表每项旧任务都改善：该模型的 τ-bench 与 ToolQA 仍有负迁移；ToolQA 最终 68.75，也低于无记忆 ReAct 的 73.53。可支持的结论是整体平均更好、平均干扰更少，不是全任务最优或完全不遗忘。[Table 2、Table 13 与指标定义](https://arxiv.org/html/2609.12655v1#S5.SS3)

### 主要收益从哪里来，额外成本又算到了哪里？

消融实验把两层记忆分开使用。以 GPT-4o-mini 为例，只给环境匹配的轨迹得 42.84，只给 GPT-4.1 提炼的技能得 37.61，两者一起得 44.13。它说明具体示例已经贡献了很大一部分收益，技能在此基础上再增加 1.29 分。不能把相对无记忆的全部提升都归功于抽象技能。[Table 3 与 Table 9](https://arxiv.org/html/2609.12655v1#S6.SS1)

换成 GPT-4o-mini 自己提炼技能，完整系统为 43.18，比用 GPT-4.1 抽技能略低。这削弱了“全靠强教师写技能”的解释，却没有排除教师贡献，因为一部分原始轨迹仍来自 GPT-4.1。它也不能证明环境过滤、聚类和技能提炼各自的独立因果贡献都已被完整测出。

成本表统计的是每个任务第一次调用模型时的平均输入：LifeMem 约 2.18k token，Synapse 约 1.88k，相差约 300 token。它包括系统提示、示例、技能和任务说明，不是完整交互的总 token 或延迟。论文另估算记忆构建约每千条轨迹一美元，这是其当时配置的成本报告，不能据此保证百万级记忆的实时开销。[Appendix G](https://arxiv.org/html/2609.12655v1#A7)

### 新任务能用上旧经验，但任务顺序仍会影响结果

一个较清楚的迁移测试是从 HotpotQA 问答转到 FEVER 事实核验：问题形式变了，但仍通过维基搜索获得证据。作者取 FEVER 的 100 个测试实例，每题最多四步。GPT-4o-mini 的成绩从 ReAct 的 0.40 变为 LifeMem 的 0.49；只提供技能时为 0.47。这里 AutoSkill 也达到 0.49，因此不能称 LifeMem 在这个设置独胜。

这个结果说明，旧任务的经验可以帮助新的任务形式，并不说明 agent 已适应任意陌生工具。论文附录明确把 FEVER 的轨迹检索限制到 HotpotQA 记忆库；它利用了环境之间已知的对应关系。对完全没有同环境示例的新工具，技能如何召回、怎样保证动作合法，仍需更明确的实现说明。[§6.2、Appendix A.6/N](https://arxiv.org/html/2609.12655v1#S6.SS2)

主实验把相近环境连续排列。将轨迹顺序完全打乱后，GPT-4o-mini 的 OP 从 44.13 降至 39.63；先在任务类型对应的小缓存中积攒五条，再成批加入，恢复到 41.64。这表明记忆整理受输入顺序影响，缓冲可以部分缓解，但没有消除差距。这里测的是有限任务流的处理策略，不是长期自主改进速度。[§6.3](https://arxiv.org/html/2609.12655v1#S6.SS3)

### 怎样精读，以及复现前还需要问清什么

先看 Figure 2 和 §4，把“轨迹进入簇—簇提炼技能—推理取两层记忆”画成流程，再看 Table 3/9 的消融，最后读 Table 13 的逐任务结果和任务顺序实验。最值得借鉴的是这套经验组织方法；论文尚未证明模型权重学会了新能力、每个环境都受益，或系统能递归改进自身的学习机制。

有几处复现问题需要明确记录。Table 1 将 τ-bench 标为 airline，附录却把训练域写为 retail、把 airline 写为未见域；不能自行替作者消除冲突。另外，正文说明了训练/测试划分，却未明确交代测试期间是否冻结记忆、是否回写测试轨迹；完全没有同环境轨迹时的技能召回也不够清楚。复现应固定各阶段记忆快照并核实这些路径，这是建议，不是原文已经证明的事实。

主结果表没有给出足以判断跨随机种子稳定性的方差，因此较小差距仍应谨慎解释。作者也把百万级经验的部署列为后续工程问题。若将其用于实际 agent，除了正确率，还应测记忆写入成本、检索错误、摘要随时间的变化和完整任务延迟；这些是从机制提出的核验方向，本次没有重新运行模型实验。[论文 v1](https://arxiv.org/html/2609.12655v1) · [作者代码与数据](https://github.com/BITHLP/LifeMem)

## 选读 · AdaMEM: Test-Time Adaptive Memory for Language Agents

**年份 / 发表信息：** 2026 · ICML 2026 · PMLR 306 · [原文](<https://proceedings.mlr.press/v306/zhang26cn.html>)

**阅读建议：** 值得精读 §3.1、算法 1 和 §3.2：先弄清运行时怎样改策略，再看哪些策略被选作训练答案；用表 1 和附录 D 核对效果与成本。

### 1. 柜子找空了，旧经验还该继续照做吗

论文有个具体任务：把两块肥皂放进垃圾桶。agent 按最初建议检查柜子，却连续扑空；它重新查经验，改去台面，找到肥皂。拿起第一块后，环境又不允许立即拿第二块，于是它再次改策略：先放下第一块，再回来取。这里展示的是途中修正做法，不只是开局找到一段相似记录。[附录 C.2、图 7](https://arxiv.org/html/2606.05684v1)

AdaMEM 来自密歇根大学和 Cisco Research，2026 年 6 月发布，正式收录于 ICML 2026。它适合接着今天的记忆主题读：重点是眼前这一步该怎样借用旧经验，以及能否训练模型把经验写成更有用的建议。[原论文](https://arxiv.org/abs/2606.05684)、[官方会议页](https://proceedings.mlr.press/v306/zhang26cn.html)

### 2. 先保存成功过程，再按当前处境查找

作者先在训练任务上收集完整操作过程，只保留最终成功的记录。每一步都保存当时处境、下一动作及后续成功过程，再把处境转成便于比较的数值向量。测试时用当前处境寻找相近记录，默认取最相近的一条；这个经验库在测试期间固定。[§3.1、§4.1](https://arxiv.org/html/2606.05684v1)

模型结合查到的记录和当前环境，临时写出短建议，例如先把手里的物品放好。论文称它为短期策略记忆，随后用它指导动作。完整交互历史仍在提示中，因此压缩的是查来的经验，不是把全部任务历史替换成摘要。[§3.1](https://arxiv.org/html/2606.05684v1)

### 3. 建议用完即丢，还是留着继续用

high 模式每步先提出一个动作，同时决定是否查记忆。选择不查，就执行该动作；选择查，才检索、生成策略、重新生成动作。新策略只用于这一步，用后丢弃。high 并不表示每步必定检索。[§3.1、算法 1](https://arxiv.org/html/2606.05684v1)

low 模式把当前策略保留给后续步骤，每步决定是否刷新；需要时才重新检索并替换策略。这样少写一些建议，但模型也可能误以为旧计划仍然有效。两种模式运行时都不修改模型参数，即训练保存下来的数值。[§3.1](https://arxiv.org/html/2606.05684v1)

### 4. 怎样训练模型写出有用的建议

Step-MFT 先用 high 模式跑训练任务，同时记录不参考策略时本来想做的动作，以及参考策略后实际执行的动作。只有任务最终成功、两个动作字符串又不完全相同，才留下这一步的策略。例如原本想继续开柜子，看过建议后改去台面，就是可能入选的记录。[§3.2.1–3.2.2](https://arxiv.org/html/2606.05684v1)

留下的策略充当训练答案：输入当前处境和检索记录，让模型练习生成该建议。这叫监督微调（SFT）；作者用 LoRA，只训练附加的小规模参数，采用 rank 32、批量 64、训练一遍数据。ALFWorld 使用 13,067 条筛选后的策略。训练完，同一个模型负责写策略和选动作；这不是执行测试任务时继续强化学习。[§3.2.3、§4.1、附录 A](https://arxiv.org/html/2606.05684v1)

### 5. 提高了多少，花了多少额外计算

表 1 使用 Qwen3-4B-Instruct-2507，在 ALFWorld 的 134 个新房间布局任务上测试。三次独立运行的成功率均值±标准差分别为：无记忆 46.8±2.5%，直接参考历史过程的 Synapse 52.2±0.7%，AdaMEM-low 58.2±3.9%。记忆方法共享训练集收集的 1,596 条成功过程，默认各取一条相近记录。附录 A 报告实验使用 48GB A40/L40S GPU，采样温度为 0.7，单次生成上限为 2,048 token。[§4.1、表 1](https://arxiv.org/html/2606.05684v1)

另看表 5 的 ALFWorld 成本配置，同一 Qwen3 模型下，low 平均每任务消耗 90K 总 token、成功率 54.0%；Synapse 为 117K、52.1%；无记忆为 77K、45.2%。这张表没有再注明 split，不能直接和前面的 unseen 成绩拼成一组结果。low 比直接塞入历史过程省 token，却仍比不使用记忆更贵；总 token 消耗也不能直接换算成美元成本或服务吞吐量。[附录 D 表 5](https://arxiv.org/html/2606.05684v1)

共享经验池让比较更容易解释：改进不是因为额外给了 AdaMEM 一批成功示范。不过，检索时机、写策略的方式和调用次数都在变化，表 1 不能单独说明其中哪一项贡献最大。作者另用逐项移除部件的实验检查机制；阅读时应把完整系统比较和这些诊断分开。[§4.1、§4.3](https://arxiv.org/html/2606.05684v1)

### 6. 动作变了，不等于证明建议造成成功

那个不参考策略的动作只是假设，没有真的执行到任务结束。因此我们不知道它是否也会成功。作者在确定性选动作等假设下论证，动作改变是策略带来收益的必要条件；实际筛选却只比较字符串，不能由此证明因果关系。训练数据中的成功也不代表每条建议都正确。[§3.2](https://arxiv.org/html/2606.05684v1)

实验都用文字环境，成功经验不足会限制记忆库，模型也可能拒绝刷新已经失效的策略。离线建库和离线微调没有证明部署后会持续自主进步。对 serving 的直接启发是跟踪检索、写策略和选动作的额外调用，再衡量复用建议是否值得；这属于系统设计启发，论文没有测生产服务的尾延迟。[§4.1、附录 C.3、E](https://arxiv.org/html/2606.05684v1)

先看图 7 的肥皂例子，再沿算法 1 走一遍 low 和 high；接着读图 3，追踪一条策略为什么被留下训练。最后对照表 1 与表 5，把任务集合、成功率和计算开销分开看。公式可以第二遍再读，先抓住运行时改建议、训练时改模型这两个过程。[全文与附录](https://arxiv.org/html/2606.05684v1)

## 选读 · Benchmarking Agent Memory in Interdependent Multi-Session Agentic Tasks

**年份 / 发表信息：** 2026 · ICML 2026 · PMLR 306 · July 2026 · [原文](<https://proceedings.mlr.press/v306/he26am.html>)

**阅读建议：** 值得精读任务构造、评分定义与附录中的失败案例；先看 §3、§4.2，再读附录 C.1、C.3–C.4，榜单只作为具体配置下的结果。

### 1. 能说出买过什么，还不等于会买下一件

先看一个教学例子：agent 第一轮替你选了相机机身，第二轮要买镜头，第三轮再买适配的配件。问它“先前买的是哪台相机”，答对只是第一步；真正有用的记忆还要影响搜索条件，排除接口不兼容的镜头，并记住已经花掉的预算。一次错误选择还可能影响后续购买。

MemoryArena 围绕这种前后依赖设计评测。每个子任务单独运行一段对话和工具调用，这段过程称为一个 session，即会话。后面的会话需要先前的选择与环境反馈。论文关注的是保存、取回、使用信息能否共同帮助任务完成，因而适合补充今天另外两篇的记忆机制讨论。

### 2. 任务怎样让早先经历变得必要

正式论文集版本有 701 组任务，覆盖搭配购物、多人旅行规划、逐步缩小范围的搜索，以及数学和物理推导。购物要保证不同商品兼容；旅行中新加入的人可能要求和先前某位旅客一起吃饭；搜索逐次加入条件；推导需要复用前面的定义和结论。作者人工核验任务与答案，让后续步骤只依赖此前已经出现的信息。[§3 与 Table 2](https://proceedings.mlr.press/v306/he26am.html)。

每组任务开始时重新初始化记忆，再在组内跨会话保留信息；旅行还提供首位旅客已确认的行程。记忆后端可以完整保留历史，也可以把历史做成可检索的记录，或先提炼再存储。RAG 指先检索相关记录、再交给模型生成。完成一个子任务后更新记忆，再进入下一个。这与跨很多独立任务持续积累经验，是不同的评测范围。

### 3. 先弄清楚“成功”究竟怎么算

论文同时报告成功率 SR 和进度分 PS。PS 先计算每组任务中做对子任务的比例，再对任务取平均；旅行还用 sPS 记录满足了多少条约束。教学例子中，一份行程满足九条要求、漏掉一条，部分进度可以很高，整份行程仍然不合格。只报告部分进度，容易掩盖这种实际失败。

SR 的定义也随环境变化：购物和旅行检查最终组合或计划是否满足整体要求；搜索、数学和物理则检查最后一个子问题是否答对。因此，后者的 SR 不是“此前每一步都正确”的比例。读榜单时应先确定评分对象，再谈记忆系统是否更可靠。[§4.2](https://proceedings.mlr.press/v306/he26am.html)。

### 4. 同一种记忆方式，换任务可能得出相反结果

为避免主表中 GPT-5-mini 与 GPT-5.1-mini 的命名不一致，这里选附录 C.1 明确使用 Claude Sonnet 4.6 的对照。在论文的 221 组渐进搜索任务中，完整历史的最终题成功率为 6%，接入 text-embedding-3-small 的向量检索记忆后为 27%。但 150 组搭配购物的整体成功率却从 13% 变成 4%。两项比较固定了任务模型，说明加检索的收益取决于任务，不能直接推出某种后端全面更好。[Table 5](https://proceedings.mlr.press/v306/he26am.html)。

这里的搜索不是只问模型一个问题：它可以反复调用搜索工具，再结合先前子问题继续搜索。搜索工具负责取得外部材料，记忆检索负责取回先前会话的记录，两者不能混为一谈。附录 B 给出主实验的采样与搜索配置，但附录 C.1 没有为新增的 Claude 4.6 对照另列完整参数；复现时还需要核对具体模型版本与运行配置。这些数字不是对产品当前默认表现的排名。

### 5. 失败可能出在三处，最终分数不能直接定位

沿着前面的相机例子检查：写记忆时可能漏掉机身接口；接口存下来了，检索时却只取回预算；接口也取回了，模型仍可能买错镜头。这分别涉及保存、取回与使用。论文的案例中既有检索漏掉关键购买属性，也有完整历史在输入中、模型仍没正确执行约束的情况。最终答错本身无法告诉我们是哪一步坏了。

附录 C.3 还尝试把先前子任务的正确结果和模型提炼的简短流程直接提供给 agent，成绩有所改善但仍不高。它只是接近理想记忆的辅助条件，并非已经证明提供了所有必要信息。较稳妥的理解是：改善记忆输入有帮助，后续推理和行动仍可能成为瓶颈；不能把剩余错误全部归因于某一个模块。

### 6. 记忆预算也要算进完成任务的成本

保存、摘要和检索都可能增加调用与等待。虽然框架允许每次动作前检索，附录 B.1 说明实际实验在每个会话开始时检索一次，以减少频率和成本。完整历史也有成本：输入会越来越长。论文因此同时报告完成子任务和整组任务的耗时，而不是只看检索器本身快不快。

这些实验使用商业模型 API，部分本地计算使用 H100。端到端耗时还受生成长度、工具调用次数和服务响应影响，不宜把表里的秒数解释成记忆算法的固定开销。带回系统工作时，可以同时记录成功率、输入输出 token、记忆操作次数和总耗时；这是本篇引出的测量建议。

### 7. 阅读路线与适用边界

建议先用 §3 的任务例子理解依赖，再读 §4.2 的评分，最后看附录 C 的对照与失败过程。这个评测能暴露“记住却没用好”的问题，但任务约束经过专门构造；它也没有把记忆质量与规划、推理、工具能力完全分离。将它用于自己的系统时，应检查具体失败轨迹，而不是只用一个总分判断长期记忆已经解决。
