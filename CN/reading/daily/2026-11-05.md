# Agent 怎样处理长材料：分开读、记重点、正确训练

主读 RLM 的2026年修订版：把长材料留在外部环境，让模型写程序选择片段、调用子模型并汇总结果。选读 MEM1，理解怎样用强化学习学会更新简短记忆；再读2026年的 MemoryWalker，追问压缩过的任务历史应该怎样拿去训练。三篇分别讨论读取、保留和重放信息。先读 RLM 的具体例子，其余按兴趣展开；不把递归调用等同于递归自我改进，也不把压缩后的短输入当成无损记忆。

每天推荐 1 篇主读与 2–4 篇选读，覆盖 LLM Inference、RL Infra、Post-Training、RSI（递归自我改进），以及推理计算、Agent 学习与记忆、数据评估和模型架构。经典与前沿并行，按主题逐步展开；不要求与当前工作直接相关。候选不等于已读，无需一天读完。

## 主读 · Recursive Language Models

**年份 / 发表信息：** 2025 · NeurIPS 2026 (author publication page); arXiv v3, 2026-05-11 · MIT CSAIL · [原文](<https://arxiv.org/abs/2512.24601v3>)

**阅读建议：** 值得精读。先用图2和算法1理解信息放在哪里，再看表1、失败轨迹和v3训练实验，判断哪些收益来自信息访问方式，哪些来自额外计算或训练。

### 先看一个问题：读完很多记录，怎样保证没有漏算？

假设一份长文件里有很多用户的问题，你要回答：问“某个数量是多少”的问题，是否比问“某件事为什么发生”的问题更多？“桥有多少米长”和“水为什么结冰”没有现成类别标签，得先理解每句话，再数数。如果只找几段相关文字，可能漏算；如果先压成摘要，也可能丢掉决定总数的记录。这是便于理解的教学例子，对应论文 OOLONG 的“逐条判断类别，再汇总”任务。[§3.1](https://arxiv.org/html/2512.24601v3#S3.SS1)

RLM 的办法是让模型自己写一小段程序，决定先看哪里、如何分块、哪些内容交给另一次模型调用，最后用程序合并结果。它改变的是模型做题时访问材料的方式。即使原始文件很长，每次神经网络实际读到的文字仍受它原有的上下文窗口限制。[§2](https://arxiv.org/html/2512.24601v3#S2)

### 第一步：把完整材料留在变量里，让模型按需查看

论文把长输入存进一个持续保留状态的 Python 交互环境：前一轮创建的变量，下一轮还能使用。这种环境叫 REPL。负责统筹的“根模型”一开始得到的是材料长度、简短开头、访问方式等信息，而非整篇文件。它可以写代码查看几行、按换行符切分、查找某个词，随后根据执行结果决定下一步。[图2、算法1](https://arxiv.org/html/2512.24601v3#S2)

完整文本和中间结果继续留在环境变量中，程序打印给根模型的内容会被截短，避免又把窗口塞满。这里所说的 context offloading 是把文字材料放到模型窗口之外，并不是论文实现了新的 KV cache 搬运算法。根模型自身的对话历史仍会增长，论文也承认每层循环需要限制；“能处理超长输入”不等于一次模型调用拥有无限内存。

### 第二步：让模型理解句子，让程序负责计数

回到刚才的例子，根模型可以先检查文件格式，再把问题分成若干批。代码在循环中调用子模型：“请判断这一批问题的答案分别属于哪一类。”返回的类别和记录编号保存在列表里，最后由 Python 计算两类记录各有多少条。理解句意交给模型，精确计数交给程序；批次大小、是否重新检查，则由根模型在任务中决定。这是机制示意，不是论文要求所有任务遵循的固定流程。[§2、附录E.3](https://arxiv.org/html/2512.24601v3)

关键不只是“多叫几个 Agent”，而是模型调用可以写在程序循环里面：一小段代码能处理很多批材料，不必由根模型逐字生成每一次完整委派。检索和摘要仍可以成为它的工具，但遇到每条记录都影响答案的任务，程序能够遍历全部记录，而不是只能依靠预先选出的少数片段。子模型也会判断错，因此程序算得精确，不代表输入给程序的类别一定正确。

### 第三步：结果留在环境中，递归深度决定谁还能继续拆题

若任务要求列出很多符合条件的用户对，程序可以把配对结果直接存进变量，然后返回该变量，不必让根模型重新逐字抄出全部答案。论文实现同时支持直接给答案和返回环境变量。保留这条输出路径很重要：长输入的问题解决后，最终答案也可能长到不适合由根模型一次生成。[§2、附录C.1](https://arxiv.org/html/2512.24601v3#S2)

论文把最大递归深度设为0到3：深度0只有根模型与代码环境，不能调用子模型；深度1可以调用普通模型；更深时，子调用也能进入 RLM 流程，继续分解问题。这里的“递归”描述调用关系，不是模型在运行中重写自己的训练方法。它可以保持模型参数不变，也可以另行训练更会使用这种环境的模型，这两件事需要分开看。[§3.2](https://arxiv.org/html/2512.24601v3#S3.SS2)

### 证据一：超长文档问答有效，但不是所有方法都被超过

主实验使用 GPT-5（medium reasoning）和 Qwen3-Coder-480B-A35B。GPT-5 方案由 GPT-5 负责根调用、GPT-5-mini 负责子调用。BrowseComp+ 测试随机抽取150道题，每题给1,000篇文档，保证答案证据在其中，输入约600万到1,100万 tokens；这是离线文档问答，不是让 Agent 在整个互联网自由搜索。[§3.1–3.2、表1](https://arxiv.org/html/2512.24601v3#S3)

表1中，深度1的 GPT-5 RLM 得分91.3%，每题平均 API 费用为0.99美元，标准差1.22美元；压缩方案为70.5%、0.57美元、标准差0.10美元。后者用 GPT-5-nano 压缩、GPT-5 回答，因此比较的是完整系统配置，不是严格同模型同预算的单一变量实验。同表把材料放进文件的 OpenCode 得分94.0%，还高于这个 RLM 配置。数据支持 RLM 是有效方法，但不支持它在文档检索上全面领先。[表1](https://arxiv.org/html/2512.24601v3#S4)

### 证据二：材料放得下，也不代表能可靠地逐项处理

OOLONG-Pairs 的主表设置只有约32K tokens，共20个查询，却要求根据记录含义列出符合条件的配对。它用同时惩罚错列和漏列的 F1 衡量结果。GPT-5 直接回答的 F1 为0.1，使用代码环境但不调用子模型时为43.9，深度1为58.0，深度3为76.0，均按0–100标尺报告。这说明收益不仅来自绕过输入长度限制，也来自把理解、保存中间结果和组合答案拆成可执行步骤。[§3.1、表1](https://arxiv.org/html/2512.24601v3#S4)

但不要把它读成“递归越深越聪明”。同一张表里，Qwen3-Coder 在代码仓库问答上关闭子调用，反而比几个递归配置更好；模型和题型都会影响最佳做法。OOLONG-Pairs 也只是特定构造的配对任务，样本量有限。这里证明了某些密集信息处理任务可以明显受益，没有证明任意复杂 Agent 工作流都会按同样幅度进步。

### v3 新增的训练：学会使用环境，不等于自主自我改进

8B 实验训练的是“如何查看变量、写代码、决定什么时候调用子模型”。作者让 Qwen3-Coder 在750道英文 LongBenchPro 题上生成2,250条运行轨迹，去掉零分或只有一轮的尝试，再把保留轨迹拆成逐轮样本，修正部分接口格式错误后教给 Qwen3-8B。这叫监督微调（SFT）：给定此前历史，学习示范的下一步输出。附录记录批量64、300个训练步、48 H100 GPU小时；图3(a)显示训练后的 RLM 在主表四类任务上改善。它不是单靠换提示词，也不是没有外部筛选的自学。[§3.2、图3(a)、附录A](https://arxiv.org/html/2512.24601v3)

另一条独立实验用 Qwen3-4B-Instruct-0527 做可验证奖励的强化学习：模型反复尝试，由可检查的答案得分指导参数更新。MRCRv2 的任务是在长材料中找出并复现指定内容；训练用32K–64K tokens、2个目标片段，共训练150步，并定期在512K–1M tokens、8个目标片段上评估。图3(b)展示这种设置下的长度泛化，不能外推成所有长程任务的泛化。两条训练线都是作者设计数据、奖励和训练流程，不是系统自主迭代提升自身研究能力。[图3(b)、附录A](https://arxiv.org/html/2512.24601v3)

### 真正的代价：会反复确认、会答错，也会拖很久

附录E.2记录了一个容易理解的失败：环境里已经构造出配对结果，模型却多次重做、检查，最后没有返回这个变量，而是自己重新生成了错误答案。附录B还指出，代码能力不足、输出预算耗尽、结束标记用错，都会使 RLM 失效。把材料保留下来只是提供了重新查看的机会，不能保证模型会看对、算对，或在正确时停止。[附录B、E.2](https://arxiv.org/html/2512.24601v3)

费用也不能只看均值。论文报告运行费用和时间都有长尾：少数请求会不断发起子调用，把总开销拉高；实验中的模型调用是阻塞、顺序执行的，因此它没有证明这些收益同时满足低延迟服务要求。表里的美元是按论文所用 API 价格估算的调用费，不是 GPU 吞吐量或今天的价格。异步执行与超时控制是作者讨论的改进方向，不能当作本文已经验证的服务优化。[§4、§7、附录F.2](https://arxiv.org/html/2512.24601v3)

### 与你做的系统工作有什么关系？

从系统角度推导，一个用户请求现在可能变成“根模型写程序→若干子调用→结果合并→再次决定”的链条。服务端不能只数原始输入有多长，还要看子调用多少、各自读多少文字、哪些调用必须等前一步结束，以及程序环境要保存多久。并行的价值取决于子任务是否独立；这些是由论文机制引出的研究问题，不是原文已经测出的吞吐量结论。

如果做实验，可以把回答质量、总 token 和调用费用、端到端耗时、失败率一起记录，再分别限制递归深度、每次切片大小和调用总数。这样才能区分：方法是用更好的信息访问方式解决了问题，还是只是花了更多预算。这是本文带来的实验设计建议；RLM 本身既不是 KV cache 压缩算法，也没有建立跨任务长期记忆或持续自我改进的完整训练闭环。

## 选读 · MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents

**年份 / 发表信息：** 2025 · arXiv 2025 · SMART / MIT / NUS / Yonsei University · first preprint 2025-06-18; v2 2025-07-17 · [原文](<https://arxiv.org/abs/2506.15841v2>)

**阅读建议：** 值得选读。先看 Figure 3 的推理与训练两条路径，再读 §3.1–3.2 和 Appendix A.7；Table 1 要连同 EM 与 peak token 的定义一起看。

### 记住什么，取决于下一步还要做什么

先看一个自拟例子。用户同时问：A 项目负责人的毕业学校是什么？B 产品使用哪种协议？第一轮检索只查到负责人叫林某，页面还附带大量项目历史。下一轮真正需要的是“负责人是林某，接下来查他的学校；B 产品尚未处理”。只写“已经查到负责人”会丢掉继续查询的线索；把整页留下又会让后续输入不断增长。MEM1 研究的就是怎样在每轮行动前生成这样的短状态，让它同时包含已知事实、尚缺信息和下一步判断。[§1 与 §3.1](https://arxiv.org/html/2506.15841v2)

论文把这段状态称为 internal state，使用 `IS` 标签表示。这里的“内部”容易让人误会：它是模型生成、随后放回提示中的文本，不是新增的神经网络隐藏层，也不是把 KV cache 换成另一种存储格式。本文选它作为 2025 年的训练型基础对照，重点看模型怎样学会保存有用信息；不把它当作刚发布的长上下文成果。[Figure 1 与 §3](https://arxiv.org/html/2506.15841v2)

### 每轮重写状态，再丢掉已经用过的材料

一次循环可以顺着例子看：模型读到旧状态和新检索结果，生成更新后的 `IS`，随后输出搜索请求或最终答案。如果新材料说明林某毕业于海城学院，状态便可保留这个答案，把待办改成查询 B 产品。程序在本轮输出完成后删除上一轮的状态、动作和工具结果，只留下本轮内容；新的工具结果随后接入。固定的任务提示仍保留，生成下一轮时也会短暂同时出现旧、新状态。因此它保留的是最近一轮所需的上下文，并非每一步只输入一条摘要。[§3.1 与 Algorithm 1](https://arxiv.org/html/2506.15841v2)

这个机制明确分开了两种变化：执行任务时，模型权重保持不变，变化的是文本状态；训练阶段才通过奖励更新权重，让模型更会写状态和选择行动。较早的原文一旦从活动上下文移除，就不能再直接被注意力读到，除非模型重新检索。这里得到的不是无损压缩保证，而是一种取舍：用较小的当前输入继续完成任务，承担遗漏必要证据后可能答错或重复搜索的风险。[§3.1–3.2](https://arxiv.org/html/2506.15841v2)

### 训练奖励来自答对问题，不来自摘要写得漂亮

作者把已有问答数据组合起来，例如一次要求回答两个问题，迫使模型在搜索其中一个问题时仍记得另一个。问答模型从 Qwen2.5-7B Base 开始，用 PPO 训练。PPO 是一种根据试做任务所得奖励调整生成概率、同时限制单次策略变化的强化学习方法。这里的关键不是手工标注每轮“应保留哪句话”，而是最终每答对一个子问题得一分：若模型删掉负责人姓名，之后找不到学校，就很难拿到那一分。[§3.3、§4.1 与 Appendix A.4.1](https://arxiv.org/html/2506.15841v2)

上下文删除由程序执行，模型学习怎样在这个约束下继续答对。问答训练没有额外的摘要质量奖励、短文本奖励或逐步奖励；但最终答案的标签不配对、答案数量不对时会记零分，所以格式仍会影响回报。EM 即 exact match，是按规定处理答案后与参考答案匹配；多目标任务的 EM 是答对子题的个数。论文另外训练了 WebShop 购物模型，使用购物环境奖励，不能把两套任务成绩写成同一模型处处通用。[§4.1、Appendix A.4.1 与 A.6](https://arxiv.org/html/2506.15841v2)

### 更新权重时，也要记得模型当时看不见什么

训练还面临一个容易忽略的问题。为了算损失，系统会把几轮生成记录拼起来；如果直接让后面的 token 看到拼接后的全部历史，它就能重新读到推理时已经删掉的页面。这样计算出的生成概率对应另一种输入条件，不能忠实表示模型当时为什么做出那个动作。MEM1 使用二维 attention mask，也就是为每个 token 指定可以读取哪些前文位置，屏蔽当轮本来不可见的旧材料。另外用损失掩码排除工具返回的文本，避免把外部检索结果当作模型自己选择的动作来训练。[§3.2 与 Figure 3](https://arxiv.org/html/2506.15841v2)

但这不是严格消除训练与推理差异的实现。Appendix A.7 说明：同一段状态在生成它的那轮和使用它的下一轮，会处于不同位置；仅修改可见范围还不够，位置编号也需要对应。作者为降低训练开销，没有复制状态并分别配置两套位置编号，而是保留前一轮的编号。因此这里可学到的是“训练要尽量重现实际可见上下文”，不能据此宣称已实现数值完全一致的概率重算。[Appendix A.7](https://arxiv.org/html/2506.15841v2)

### 长任务优势要同时看答对数、输入规模和计时条件

问答训练使用两个目标的组合，测试扩展到最多 16 个目标。Table 1 中，16 目标时 MEM1 平均答对 1.97 个子题，Qwen2.5-14B-Instruct 为 0.567 个，构成摘要约 3.5 倍的提升；但 1.97 不是 197% 成功率，也离完成全部 16 个目标很远。同为 7B 的指令模型直接套用截断流程，平均答对 0.396 个，说明在这组比较中仅删除历史不足以取得 MEM1 的结果。不过模型的训练经历并不完全相同，不能把全部差距单独归因于某一个记忆操作。[Table 1 与 Appendix A.4.1](https://arxiv.org/html/2506.15841v2)

同一 16 目标比较中，MEM1 的峰值上下文规模为约 1,040 tokens，对照 14B 模型约 3,840；整条任务轨迹耗时为 8.70 秒与 29.7 秒。峰值 token 使用 GPT-4o-mini tokenizer 统计并排除 system prompt，只是推理显存需求的代理指标，不是实测显存字节。计时条件是单张 H200、10 个并发线程、vLLM 开启自动 prefix caching；训练使用 4 张 H100 或 H200。结果也非处处占优：Table 3 单目标 Wiki-QA 上，MEM1 的 EM 为 0.405，低于 Search-R1 的 0.445。[Table 1、Table 3 与 Appendix A.1、A.4](https://arxiv.org/html/2506.15841v2)

### 精读时追问：短状态保住了什么，又丢掉了什么？

建议先沿 Figure 3 和 Algorithm 1 手动走两轮，再读 §3.2 与 Appendix A.7，把“推理时删历史”和“训练时遮住历史”对应起来。最后结合 Table 1、Table 3 看准确率与成本的取舍。实验给较小任务最多 6 轮、较大任务最多 20 轮，并显式提示剩余轮数；在线搜索测试返回标题、摘要和 URL，不要求读取完整网页。因此它验证的是有限预算下的交互与记忆能力，不是跨月持续学习，也不是无限长度上的可靠性证明。论文自己还指出，训练依赖可验证奖励，开放研究任务中怎样判断保留的信息是否足够仍未解决。[§4.1、§5 与 Appendix A.2](https://arxiv.org/html/2506.15841v2)

对系统设计的启发属于进一步推论：当新状态重写了旧前缀，服务端应重新评估哪些缓存仍可复用；不能把语义上延续同一个任务等同于 token 前缀未变。这可以成为后续实验问题，论文没有给出通用调度结论。本笔记依据 Zijian Zhou、Ao Qu 及合作者的 [MEM1 v2（2025-07-17）](https://arxiv.org/abs/2506.15841v2)，原文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。以上为解释性改写与评议，项目、人物和学校示例为自拟，并非原文实验。

## 选读 · MemoryWalker: Stop Training Agents on Contexts They Never Saw

**年份 / 发表信息：** 2026 · arXiv 2026 · Token Foundry / Alibaba Group · v1 2026-09-01 · [原文](<https://arxiv.org/abs/2609.00865v1>)

**阅读建议：** 值得选读§3、Figure 2和Appendix G，先掌握上下文重放，再看§5与Table 1；证明可留到第二轮。

### 摘要写出来以后，不能假装过去一直看着它

先看一个自拟例子。Agent查到一段很长的资料D，读完后生成判断A；随后把D替换成短摘要S，再根据S和A生成下一步B。A实际是在D仍可见时产生的，B是在D已被替换后产生的。把整次任务拿去训练时，A应该在前一种上下文下算概率，B应该在后一种上下文下算概率。最终留下的一条聊天记录，未必能同时还原这两个条件。

MemoryWalker研究的正是这种错位。这里的上下文压缩是删除消息或用摘要替换文本；它不是把KV cache从显存搬到主存。后者可以保留相同计算内容，前者直接改变模型读到的输入。即使权重完全同步、计算精度相同，输入变了也可能产生不同概率。论文把应当满足的要求称为conditioning consistency：训练每个目标token时，恢复它生成当时真正可见的前缀。[§3](https://arxiv.org/html/2609.00865v1#S3)

### 只留最终记录不对，把所有内容塞回来也不对

第一种朴素方案直接训练最终压缩记录。例子中，这等于用S重算A，但A生成时还没有S。后来的编辑被提前应用到过去，论文称之为time-travel leakage。这个名字不一定意味着摘要泄露了标准答案；更一般的问题是，评分时使用了错误时刻的上下文。对于纯删除，甚至可能只是把当时可见的一段信息提前去掉了。

第二种方案把D等被删文本都加回原始历史，再用一条普通因果序列训练。这样算A可能合适，却会让后来的B看到部署时已经不再可见的D。恢复每个目标的真实条件，需要记录编辑何时发生、删掉或替换了什么，以及当时实际发送给模型的内容。论文用“树”表达这些不同前缀：共享起点，但编辑前后沿不同分支继续。[§3.2–3.3、Figure 1](https://arxiv.org/html/2609.00865v1#S3.SS2)

### 精确重放：分别算分支，或把分支隔离后打包

LogitTree将K次编辑形成的K+1条路径分别送进模型，只在目标原本生成的分支上计入损失；loss mask指定哪些位置计入，避免公共前缀重复计数。代价是多次前向和反向。4D mask则打包隔离各分支，位置编号与各自前缀一致。论文的梯度等价结论限于同一batch、稠密softmax attention和Proposition 4的五项条件，包括正确可见性、位置及无跨分支归一化。[§4、Appendix C.2](https://arxiv.org/html/2609.00865v1#S4)

实现时尤其要读Appendix G。正文用“每个token只放一次，再改变可见性”描述4D方法，但作者说明实际训练会为各分支复制公共token，再用块对角attention mask隔离，位置编号按分支重启。这样每份隐藏状态都来自自己的前缀。实际打包长度是各分支长度之和，可能明显大于去重后的原始历史；因此一次forward不等于少算了所有重复前缀。这里解释的是论文披露的实现，未检查当前源码。[Appendix G](https://arxiv.org/html/2609.00865v1#A7)

### SDCC省掉多次反向，但仍要付教师前向成本

SDCC保留最终压缩记录作为学生输入；在上下文不一致的位置，再用生成时实际可见的前缀运行同一个模型，得到不参与反向传播的教师分布。教师不是额外训练的更大模型，而是同一组权重在另一份输入上的预测。训练除了原任务损失，再加 KL(教师分布 || 学生分布)，让压缩输入下的预测尽量接近原输入下的预测。KL在这里衡量两种概率分布的差异；公式方向依据正文Equation 10。[§5.1](https://arxiv.org/html/2609.00865v1#S5.SS1)

学生只反向一次，教师仍可能按编辑节点做多次无梯度前向，也仍需要恢复相关旧前缀。它节省的是反向成本，不是让历史记录和教师计算消失。“黑盒harness”在论文里仍允许观察模型请求来恢复上下文，不是只拿最终回答就能训练。SDCC是近似：论文的KL界约束对应位置的分布差异，不保证全任务答案相同，也不保证有损摘要总能保留所有必需信息。[§5.2、Appendix E–F](https://arxiv.org/html/2609.00865v1#S5.SS2)

### 看证据时，把概率一致与答题正确分开

作者用Slime的Megatron训练端与SGLang生成端，在80GB A100或H800级GPU上评估，未在本文引用处给每个结果明确卡数。Qwen3-4B主表使用81,638条组合问答训练数据、GRPO每题16个样本，并在七个问答基准上测试。以AgentFold编辑器为例，Table 1的平均精确匹配率为：直接训练压缩记录33.2%，LogitTree 37.5%，4D mask 34.2%，SDCC 42.4%。这是作者报告的不同训练运行成绩，不是把相同batch换一种打包方式就必然提高这些百分点。[§6.1–6.2、Appendix F.1](https://arxiv.org/html/2609.00865v1#S6)

同一组中，记录token的平均log-prob差异分别为0.366、0.012、0.022、0.071；无压缩对照约0.014。因此“精确恢复上下文”仍不代表数值误差为零，差异较低也不自动对应更高答题分数。读表还要注意：logdiff取各运行最大奖励迭代，EM则取开发集初筛后、全测试套件评估的最高结果，两列未必来自同一时刻；网页检索也会变化。论文未给这些对比多随机种子置信区间，不能把小差距当成稳定排序。这里引用主表口径，未把附录中另一种聚合方式的drift混进来。[§6.1、Table 1、Appendix F.4–F.6](https://arxiv.org/html/2609.00865v1#A6)

### 阅读价值：先确定模型当时看到了什么

建议从Figure 1和§3开始，自己给例子中的A、B分别写出可见前缀；再看Figure 2、Appendix G理解重放成本，最后读Equation 10与Table 1。对系统工作的直接启发是：除了权重版本和生成token，rollout数据还需要保留足够的信息来恢复每次请求的输入。RLM的子调用、记忆摘要或工具历史裁剪都值得做这种核对；但本文没有证明本期几种方法组合起来的效果，也没有证明所有现成框架都有这一问题。
