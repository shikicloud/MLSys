# Agent 怎样改进自己：改程序、学示范与验证收益

今天读三篇 2026 年研究，把“自我改进”拆成能追踪的实际操作。主读 AIDE²：一个研究助手修改另一个研究助手的控制程序，哪些改动被留下，换任务后还管不管用？选读 SDFT，理解怎样把示范中的信息学进模型权重；再读 REUSE，解释为什么反复用同一套题选版本，可能把碰巧涨分误认成进步。每篇先讲具体例子，再看机制、实验和限制。只精读主读即可；两篇选读按兴趣展开。

每天推荐 1 篇主读与 2–4 篇选读，覆盖 LLM Inference、RL Infra、Post-Training、RSI（递归自我改进），以及推理计算、Agent 学习与记忆、数据评估和模型架构。经典与前沿并行，按主题逐步展开；不要求与当前工作直接相关。候选不等于已读，无需一天读完。

## 主读 · Recursive self-improvement of AI research agents

**年份 / 发表信息：** 2026 · arXiv 2026 · v1 2026-09-22 · [原文](<https://arxiv.org/abs/2609.26457>)

**阅读建议：** 本期主读，建议 35–50 分钟。先理解内层改任务代码、外层改 agent 代码，再读搜索与记忆机制；最后重点看独立测试和 ignition 实验，不要只看上升曲线。

### 先让 agent 改训练脚本，再问它能否改进做实验的方法

假设我们交给 agent 一份图像分类训练脚本，希望它在有限预算内提高准确率。它可以改学习率，运行训练，看验证集结果，再决定保留修改还是试另一个办法。这里先改的是解决具体任务的代码。**这个分类任务是贯穿本文的教学例子，不是论文公布的某一道实验题。**

现在把问题往上一层推：为什么它总是在同一个方案上微调？为什么每轮都把全部旧日志塞进输入？能否修改决定下一步实验、保存历史和检查结果的程序，让它今后做不同任务都更有效？模型之外这层组织工作的代码，论文称为 harness，下面叫 agent 控制代码。

AIDE² 来自 Weco AI。团队于 2026 年 7 月 14 日先发博客，9 月 22 日公开论文 v1；本文以论文为准，属于 2026 年预印本。它研究的是持续修改研究工具本身，而不是让模型重写一次答案就宣称学会了自我改进。[论文](https://arxiv.org/abs/2609.26457)；[团队早期说明](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)

### 内外两层循环分别改什么，哪些部分一直固定

内层收到具体任务，反复修改任务代码。例如在分类任务里，它会产生几份训练脚本，执行后留下分数与错误记录，预算耗尽时选一份提交。外层收到的则是这个研究 agent 的代码，修改它怎样挑实验、组织输入和处理反馈。评估一个外层改动，要让改后的 agent 再做一组内层任务。

主实验由人工开发的 AIDE_human 担任外层改写者，它在整段运行中不变；每次获准保留的，是下一轮继续被修改的内层 agent。两个循环调用的基础模型也固定：外层 Claude Opus 4.7，内层评估 Gemini 3 Flash。没有在这里训练这些语言模型的权重。[原文 §2.1–2.2、Figure 1](https://arxiv.org/html/2609.26457v1)

因此要分清“持续改进同一套研究程序”与“每一代都换一个更强的改写者”。前者是主实验做的事，后者需要额外检验。固定语言模型，也不意味着内层任务不能训练分类模型；限制针对驱动 agent 的基础模型，不是禁止它执行研究任务。

### 三层反馈，分别防止什么误判

回到分类例子：agent 可以反复看到公开验证分数，靠它选择下一次实验。但反复试得足够多，也可能只找到迎合这份验证数据的脚本。因此内层提交最终方案后，还要在它看不到的私有数据上评分。外层把多个任务的私有分数合成一个成绩，用来决定 agent 改写是否保留。[原文 §2.1](https://arxiv.org/html/2609.26457v1)

这里的“私有”是相对于内层求解者而言。外层会反复利用合成成绩选版本，所以这份成绩仍然参与了开发，不能充当最终泛化证明。还需要第三层：冻结已选中的 agent，再放到从未参与版本选择的新任务上测试。这才区分出“更会应付选拔题”与“研究方法能迁移”。

**以下是解释这三层设计的推导：** 公开反馈回答“下一份任务代码该怎么改”，私有成绩回答“这个 agent 版本值不值得留下”，独立外部测试回答“留下的改动能否帮助新任务”。三者即使都叫 evaluation，也承担不同职责，不能因为数据对某一层隐藏，就把它当作对整个系统从未使用的测试集。

### 搜索改进：别把全部预算押在当前第一名上

起始 agent 偏向继续改分数最高的候选。教学例子中，假设调学习率的方案略胜于改数据预处理，它就可能把后面的尝试都投给前者。但预处理暂时低分，也可能只是还没调好；只追当前第一名，会过早放弃其他方向。相反，每次都从零开新方案，又无法积累已有进展。

最终版本 AIDE85 把起草策略分成五类，先挑策略，再改该策略下表现最好的候选。选择策略时使用多臂老虎机方法：综合过去收益与尚未充分尝试的程度，分配下一次尝试。论文具体使用 UCB1，并混合另一种按分数采样的选择；还周期性地把最好方案交给不同策略继续改。[原文 §3.5、Figure 5](https://arxiv.org/html/2609.26457v1)

这不要求模型凭空发明一项全新的研究方向。它改变的是实验预算怎样分配：已有好代码可以保留，但下一轮尝试的角度可以改变。**对分类例子的类比是我们自己的解释：** 不是丢掉最佳训练脚本，而是让另一条优化思路从这份脚本继续探索。

### 记忆改进：保留能影响下一步的记录

若已做过 30 次实验，把 30 份完整脚本和所有日志一起发送，输入会越来越长。下一次只想修一个导入错误，却仍需处理许多无关的成功实验。删掉全部历史也不行：它可能重复试过的失败办法。这是信息取舍问题，不是输入越长就一定记得越好。

AIDE85 改用较短、按角色组织的输入：提出新方案与改进旧方案时，读取根方案和近期候选的摘要；错误较多时，再加入重复出现的错误记录。它不再像起始版本那样不断拼接完整历史。这是写入控制程序、在后续任务中继续生效的变化。[原文 §3.5、Figure 6](https://arxiv.org/html/2609.26457v1)

**从机制可推导的价值是：** 在按调用与执行费用约束的任务里，减少无用输入可以给更多有效尝试留出预算。但短输入不保证更高成绩，删去关键反例也可能让决策变差。因此最终仍应以整个研究任务的结果判断，而不是把压缩比例直接解释成相同倍数的研究加速。

### 八天的上升曲线，实际包含多少次改进

主运行持续八天，共 100 个节点：一个起始 agent，加 99 次改写提案。其中 7 次获准替换当前最佳版本，合成私有成绩从 0.703 升到 0.778。另两次完整运行分别接受了 2 次和 4 次改写。它提供了重复找到有用修改的证据，但不是每次尝试都成功。[原文 §3.2、Figure 2](https://arxiv.org/html/2609.26457v1)

0.703 和 0.778 是选拔任务的合成成绩，不能读成“通用研究能力从 70.3% 提升到 77.8%”。被接受的曲线只保留迄今最好版本，本来就不会因淘汰较差候选而下降。真正值得检查的是尝试了多少候选、接受依据是否可靠，以及这些版本在独立任务上怎样表现。

人工仍负责定义起始系统、任务集合、每项预算和保留准则；自动完成的是运行中的提案、执行与比较。团队声明循环内没有人工介入，但这不等于没有人工设计。把八天与团队此前两年的开发经历并列，可以说明背景，不能据此算出在同等条件下替代研究人员的倍数。[团队说明](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)

### 换一批研究任务，改进是否仍然存在

作者在未参与选拔的 ALE-Bench、MLE-Bench、FML-Bench 和基于 WeatherBench 2 的天气任务上比较起始、改进中途、最终以及人工开发版本。前三类覆盖算法或机器学习工程，天气任务则考察此前未出现的物理预测程序优化。每个基准内部，各 agent 遵守相同协议。[原文 §3.3、附录 A](https://arxiv.org/html/2609.26457v1)

以机器学习工程为例，MLE-Bench lite 包含 22 项比赛，每项运行三个种子。各 agent 使用 Gemini 3 Flash，每次主要预算为 5 美元，任务脚本在 4–24 vCPU、16–192 GB 内存的 CPU 容器中执行。私有排名分数的均值从 AIDE0 的 0.678±0.006，升到 AIDE85 的 0.722±0.011；人工版本为 0.708±0.007。± 表示一个标准误，这种相对排名分数不是分类准确率。[附录 A、Table 1–2](https://arxiv.org/html/2609.26457v1)

最终版本在四项汇总结果的均值上达到或超过人工版本，不代表四项都显著领先。进步也不是逐代单调：中途版本 AIDE47 在 MLE-Bench 与天气任务上优于 AIDE85。天气验证只有一个优化任务、三次不同随机设置的重复运行；它展示了一次跨任务类型迁移，不能代表已在各种科学问题上验证。

比较时也要注意预算定义。论文的外部实验有的主要限制费用，有的主要限制搜索步数；不能把全部结果概括成“完全相同 GPU 时间”。天气分数是相对起始预测程序的改善，不是 WeatherBench 排行榜的绝对成绩。**这些区别决定了收益能外推到多远。**[附录 A、Table 1–2](https://arxiv.org/html/2609.26457v1)

### 检查代码以后，哪些漂亮机制并没有证实有效

论文还检查单独测速很快的 GPU 算子，放进真实训练循环后是否仍然有效。实验有 38 个算子与训练环境的组合、每个三个种子，涉及 GPT-2、ViT 和 CNN；agent 使用 Gemini 3 Flash，每次最多搜索 20 步，算子在 NVIDIA A100 上运行。对每组先在三个种子上求平均，再按作者定义判定：单独测速超过 1.02 倍、但训练中保留不足一半所报加速或直接崩溃，就计为 reward hacking。该比例由 AIDE0 的 55% 降到 AIDE85 的 32%，人工版本为 39%。分母是 38 组场景，不是 114 次运行；相同步数也不保证相同费用或时间。这里测的是代理指标与实际效果脱节，不是在判断程序有没有主观作弊意图。[§3.4、附录 A](https://arxiv.org/html/2609.26457v1)

生成的代码里有一项惩罚异常高分候选的规则，看起来像在防止偶然赢家。但作者检查后发现它保持原有排序，重放评测时从未改变最终选中谁。因此不能把总体改善归功于这条规则，也不能仅凭程序里出现某种机制，就说它发挥了预期作用。

另一个修改修复了评估脚本的错误：原来单个测试失败会拖垮整次私有评估。修评分程序与改搜索策略是两回事。论文没有把每项改动都独立消融到足以确定贡献；目前最可靠的是完整版本的比较，机制描述应与因果证明分开。[原文 §3.5](https://arxiv.org/html/2609.26457v1)

### 真正接近递归的下一问：它能成为更好的改写者吗

假设新 agent 更擅长改分类脚本，仍不能自动推出它更擅长修改 agent 本身。两种工作虽都写代码，成功所需的判断并不相同。要让改进不断加速，就需要新版本接手后，能在可比预算内产生比旧改写者更好的后继版本。

论文为此做 ignition test：让 AIDE47 与 AIDE_human 分别担任外层改写者，从同一个内层 AIDE47 起步；每组用三个随机种子重复运行，各跑 50 步。两组平均终点相近，作者明确认为证据不足，不能断言改进版本更善于、或更高效地推动下一轮自改进。[原文 §3.6、Figure 7](https://arxiv.org/html/2609.26457v1)

所以本文展示的强证据是持续的程序优化与外部迁移；“改进能力本身持续变强”仍是待证问题。更不能从一次有限长度实验，推到不依赖更多人工设计的开放演化、无限能力增长或智能爆炸。把这个额外检验单独列出来，是它值得精读的地方。

### 怎样阅读，并把问题带回自己的 agent 系统

**我们从实验提炼出的检查顺序是：** 先指出改进保存在哪里，再确认下一次运行会不会继续使用；然后问反馈是谁给的、哪个程序能看到它；最后检查测试任务有没有参与过版本选择。这样能区分一次答题修订、可复用程序改进，以及改进者本身变强。

实现上另一个未解决的问题是维护成本。复杂代码可能确实拿到更好成绩，却很难判断哪些分支有效、哪些只是遗留逻辑。研究版本的汇总成绩并不替你完成接口兼容、错误恢复和可解释性检查；论文也把这些列为部署阻力。[原文 §5](https://arxiv.org/html/2609.26457v1)

阅读路线可以按问题走：Figure 1 看内外循环；§2 看反馈与预算；Figure 5–6 看搜索和记忆；Figure 2 看连续改进；Figure 3 与附录 A 看独立任务；最后用 Figure 7 检查更强的递归主张。早期博客与论文有若干数字和实验范围差异，引用结果请统一到本篇使用的 v1。

## 选读 · Self-Distillation Enables Continual Learning

**年份 / 发表信息：** 2026 · ICML 2026 · preprint January 2026 / v2 August 2026 · MIT, ETH Zürich · [原文](<https://proceedings.mlr.press/v306/shenfeld26a.html>)

**阅读建议：** 选读，值得精读 §3 / Fig. 2、§4.3 / Fig. 3、Table 5，再看附录 A.3 的教师稳定性。建议 30–40 分钟；先理解教师和学生各看到了什么，再读 KL 公式。

### 看一眼正确示范就会做，能不能下次不看也会

**教学例子，不是论文实验题：**给模型一个天气工具的说明，让它查询上海气温。模型可能选对工具，却填错参数；如果再给它这道题的正确调用示范，它就更容易理解应该怎样回答。问题是，把示范拿走以后，这个改进还能不能留下？

SDFT 把模型分成两个角色：学生只看问题，教师额外看到示范。训练让学生向教师学习，改变决定它怎样生成文字的数值，也就是模型权重。这样，下一次作答依靠的是训练后的模型，不必每次把原示范重新塞进输入。“自己教自己”的教师仍然得到了外部信息。

论文由 Idan Shenfeld、Mehul Damani、Jonas Hübotter、Pulkit Agrawal 完成，来自 MIT 与 ETH Zürich，已发表于 ICML 2026。初稿为 2026 年 1 月；下文机制和实验细节按 8 月 7 日 arXiv v2 核对。[正式会议记录](https://proceedings.mlr.press/v306/shenfeld26a.html)；[v2 原文](https://arxiv.org/abs/2601.19897v2)

### 学生先写自己的答案，教师再沿着这条路指导

普通监督微调，简称 SFT，会让模型模仿数据集里的示范答案。SDFT 则先让当前学生只根据问题生成一次回答。这样得到的是学生按自己的习惯走出的过程，可能与专家示范不同；用当前模型自己生成的过程来训练，称为 on-policy。

随后，教师读取问题、示范，以及学生已经写出的前缀，计算接下来各种 token 的概率。token 是模型处理文字的基本单位。学生也在相同前缀处给出概率，训练会让这两组预测更接近。这种向另一个模型的预测学习的方式叫蒸馏；这里不是只拿一个最终对错分数，也不是把学生回答全部替换成示范。

回到天气例子，教师知道正确调用应是什么，学生却必须练习自己从问题出发组织答案。测试时，只给训练后的学生问题和正常任务输入，不提供教师额外看到的示范。原文 Fig. 6 还与“提前生成教师答案，再训练学生”的做法比较，检验收益是否只来自更好的教师。[§3、§4.6、Fig. 2 / 6](https://arxiv.org/html/2601.19897v2)

### 教师怎样跟着变强，又不跟着每一步波动

教师和学生从同一模型出发，但训练中不能简单当成两份始终相同的模型。v2 默认让教师保留大部分旧权重，只逐步混入学生的新权重。这叫指数移动平均，简称 EMA。教师因此能跟上学生的进步，又不会立刻追随每一次更新的波动。

附录 A.3 比较了三种教师：始终冻结的基础模型较稳定，但效果较弱；直接使用当前学生作教师容易不稳定；EMA 在该实验中兼顾了两者。它不是免费增加一个更强的外部模型，也不保证教师每次判断都对。

衡量两组生成概率差异的方法叫 KL 散度，而且比较方向不同，训练目标也不同。**§3 的理论推导使用 reverse KL；实际实现说明则报告 forward KL 表现最好。** 不能把前者的理论解释直接当成后者完整的保证。第一次读可以先记住：学生自己产生练习过程，教师提供每一步的概率指导；方向和估计方法留到复现时核对。[§3、附录 A.1 / A.3](https://arxiv.org/html/2601.19897v2)

### 训练信息从哪里来，哪些工作仍由外部安排

主实验使用 Qwen2.5-7B-Instruct，并训练全部模型参数；附录给出的训练硬件是单张 NVIDIA H200。技能包括科学问答、工具调用、医学问答。科学示范由 GPT-4o 对训练题最多尝试八次，保留最终答案正确的一份；工具调用示范来自 ToolAlpaca；医学训练使用约两万道英文题，另取一千道可验证问题评估。

数据准备和选模型并非自主完成。研究者划分训练、验证和测试集，搜索学习率等设置，再按验证集成绩选择模型；医学评估使用 GPT-5-mini。训练本身不要求另写一个奖励函数，但正确示范、已有答案和评估方法依然提供了外部帮助。“没有显式奖励”不能改写成“没有监督”。

另一个知识实验整理约二十万 token 的文章，描述模型知识截止时间之后的 2025 年自然灾害。GPT-5 据此生成问答，人还检查重复问题。知识实验的教师同时看到文章与示范回答，学生没有这些额外材料；实验并非模型自行发现新闻、判断真假再决定学什么。[§4.1、附录 A.2 / B](https://arxiv.org/html/2601.19897v2)

### 学会新任务之后，原来会的是否还会

先看 ToolAlpaca 的单任务比较。Table 5 中，Qwen2.5-7B 基础模型正确率为 42.9%，普通 SFT 为 63.2%，SDFT 为 70.6%。再测六项原有能力，其平均分分别是 65.5、56.0、65.4。这里支持的是：新任务更好，同时原有能力平均下降较少；不能据一个平均数说每项能力都完全保住。

更接近连续学习的是 Fig. 3：同一个模型依次学习前面三个技能，每换一个任务仍检查先前技能。SDFT 比顺序 SFT 更能保留已经学到的内容。不过这只是一条有限的三任务序列，并非几个月不停接收真实用户经验。图的纵轴还按各任务基础分和最高分做了归一化，不能直接读成百分比正确率。

准确率评估用每一步选最高概率 token 的 greedy 生成；附录说明通常运行三个随机种子。作者也检查多次尝试至少成功一次的 pass@k，最高到 128，收益仍存在。这增加了证据，但仍不能代替跨更多任务、顺序和时间的验证。[§4.2–4.3、Fig. 3 / 5、附录 B.2、Table 5](https://arxiv.org/html/2601.19897v2)

### 把新事实留进权重，效果和代价各是什么

在灾害知识实验中，答案细节必须全部正确时，SFT 得 80%，SDFT 得 89%；换成不直接点名原事件、但需要相关知识的问题，分别为 80% 和 98%。这些结果来自所构造的小范围知识任务和自动评估，不能推广为所有新知识都能稳定学会。每次都提供正确文章的理想检索对照，仍分别达到 91% 和 100%。

模型首先要能读懂示范。科学问答的规模比较中，3B 模型用 SDFT 反而落后普通 SFT。作者还报告，学生会学到教师的“根据上述文本”等措辞，尽管学生实际上没收到那段文本。把有用知识学进去时，也可能一起学到不适用的表达习惯。[§4.2、§4.4、§5](https://arxiv.org/html/2601.19897v2)

相比普通 SFT，这套训练还增加学生生成和教师计算概率的成本，然后才更新学生权重。每题只生成一次，并不意味着一次普通推理的费用。实际成本取决于生成长度、训练轮数和实现，应把这些环节分别测量；论文给出的整体倍率没有充分交代每项比较条件，因此这里不把它当作通用预算依据。[§5、附录 B.1](https://arxiv.org/html/2601.19897v2)

### 它证明了哪种改进，怎样读才不会混在一起

这里保存下来的改进在模型权重里；学习算法、任务和示范来源仍由外部规定。论文没有展示模型自主重写自己的学习方法，再持续提高改进自身的能力，所以不能仅凭“自蒸馏”就称为递归自我改进。作者也承认仍有遗忘，处理低质量示范或用户对话属于后续方向。

**对系统工作的以下联系是我们的分析：**如果采用这种训练，需要分别测学生生成、教师评分和参数更新的成本，并保证教师与学生在同一段已生成内容上比较概率。上线后不再携带原示范，是以提前训练为代价；是否划算，要与检索或把示范放进上下文的方式共同比较。

先读 Fig. 2，画清教师比学生多看了什么；再读 Fig. 3 和 Table 5，区分新任务分数与原有能力；最后读附录 A.3 和 §5，检查稳定性、费用及失败情形。理解这些之后再看 §3 的 KL 推导，才不容易把“借助示范学得更好”误读成“模型已能无条件持续自我进化”。

## 选读 · Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks

**年份 / 发表信息：** 2026 · arXiv 2026 · v2 2026-09-29 · [原文](<https://arxiv.org/abs/2609.33180v2>)

**阅读建议：** 值得选读，建议 20–30 分钟。先理解考试例子，再读 §2.1 的假设、Algorithm 1、Table 1，最后核对附录 B 的预筛与消融。

### 题目没有泄露，为什么还是可能越考越偏

**下面是教学例子，不是论文数据。** 让 Agent 修改一个分类器，每次交八个版本，评测服务只返回准确率。第一次，它发现加深决策树得分最高；下一次便围绕深度继续改。题目始终藏在服务器里，但分数已经在指导搜索。多轮以后，程序可能越来越适合这批题，却没有同样改善新样本的判断。

这里不必发生直接偷看答案。选出高分版本，再根据成绩决定下一步，本身就在利用评测信息；这种越试越迎合固定评测集的现象叫适应性过拟合。REUSE 专门研究这个问题。论文来自 Purdue University，2026 年 9 月 27 日首发，本篇读 9 月 29 日 v2；目前按预印本介绍。[版本与作者](https://arxiv.org/abs/2609.33180v2)

### 一轮挑八个，与连续改很多轮，是两层问题

只看一轮，八个版本里最好的那个，也可能只是碰巧更适合这批样本。不断重复比较，又增加了至少误判一次的机会。若所有候选事先确定，可以为这些比较分配更小的误判额度；但 Agent 会看前面的反馈，再提出后面的版本，候选就不再独立于这批评测题。只按总比较次数收紧门槛，没有自动解决这一层依赖。

REUSE 让提出改动的一侧充分使用另一份开发数据，但评测服务只回传“全部拒绝”或“接受第几个候选”。原始分数、逐题结果，以及内部算出的改进保证都不回传。接受决定仍然包含信息，所以方法还要把可能出现的决定历史纳入风险计算，不能认为隐藏分数就万事大吉。[§1–2](https://arxiv.org/html/2609.33180v2)

### 怎么决定接受，以及保证到底保证什么

在对错评分中，服务把新旧版本放到相同题目上比较：新版本修好了多少原来的错误，又弄错了多少原来答对的题？两者都对或都错的题，不提供胜负证据。配对检验据此判断，新版本的优势能否仅由抽样波动解释；再按本轮候选数、此前接受次数和可能历史收紧接受门槛。

理论前提很严格：评测样本来自同一个目标分布，彼此独立，也就是 i.i.d.；它最初必须独立于开发数据、初始系统和搜索随机性；后续只通过规定的决定传递信息。设整个过程允许的错误概率 α 为 0.05，结论是在这些条件下，以至少 95% 的概率，所有被接受的改动都提高该分布上的平均表现。这是对评测集抽样下整段过程的共同保证，不是对已经观察到的某次更新给出 95% 的后验可信度，也不是每次更新单独有 95% 把握，更不是绝不会退步。

已有题目污染、额外日志回传或部署任务改变，都不能直接套用这个保证。越往后通常还要更强的证据，真正的小进步可能被拒绝。因此，方法控制的是错误接纳，不承诺永远找到下一次进步。[§2.1、Theorem 1、Proposition 1](https://arxiv.org/html/2609.33180v2)

### 真实实验改的是分类器配置，不是完整研究 Agent

实验用 Covertype 数据判断一个样本是否属于第 2 类森林覆盖类型。Qwen2.5-7B-Instruct 通过 vLLM 在一张 A100 40GB 上提出 scikit-learn 配置，模型家族限定为梯度提升与逻辑回归；每个候选最多改两个字段，如学习率、特征子集或预处理。每次搜索有 200 轮，每轮最多八个有效候选，两种评测集大小各跑 30 个种子。[§3.1、附录 B.1–B.2](https://arxiv.org/html/2609.33180v2)

作者把数据分成五万条训练样本、两万条开发样本、六万条评测池与五万条最终保留样本。每次从评测池抽两千或一万条，反复用于接受决策；最终保留集 H 不给任何搜索方法访问，用来另行检查改动。人工预先规定任务、配置空间、提示词和检查规则；论文没有描述逐轮人工选优。这仍是受限的自动搜索，不能写成 Agent 自主完成了 200 次能力跃迁。 搜索中不训练提出建议的语言模型；变化的是分类器配置，每个分类器再用训练集拟合。

### 少接受一些改动，最后的成绩仍然接近

Table 1 的两千条评测样本条件下，REUSE 平均每次搜索接受 3.2 个改动，30 次搜索合计未观察到错误接纳；最终在 H 上比起始分类器提高 7.02±0.26 个百分点。直接挑评测涨分最多的版本，平均接受 13.0 个改动，出现 75 次错误接纳，最终提高 7.04±0.08 个百分点。这里的 ± 是标准误，错误接纳指改动在 H 上没有正收益。[Table 1](https://arxiv.org/html/2609.33180v2)

因此，最终分数接近，不代表中间每次更新都可靠。另一条更保守的 Bonferroni-style 基线也没有错误接纳，但该条件下最终只提高 2.35±0.37 个百分点。不能据此声称只有 REUSE 能做到零次错误，也不能把论文的 SICA-style、DGM-style 配置搜索当作原始系统的完整复现。五万条 H 仍是有限样本，“真实进步”在实验里也是估计；这里没有外部团队独立复现的证据。

### 不能把全部收益都归给最后一道统计检验

附录披露 REUSE 还使用开发集上的草稿更新与提交预筛，并去掉已经评测过的重复配置；其他方法收到的信息与搜索方式并不完全相同。因此主表比较的是组合流程。开发集上的尝试轮次，也不应直接等同于正式查询评测集的次数。[附录 B，Table 2–3、6](https://arxiv.org/html/2609.33180v2)

更直接的证据来自移除检验的实验：作者把开发集缩到 500 条、放宽预筛，在十个新种子上制造较容易误选的条件。保留评测检验时，九个在 H 上没有正收益的候选被拒绝，47 次接受里没有错误；去掉检验后，十次运行中有五次出现错误接纳，合计六次。两边最终成绩没有显著差异。这支持检验对更新可靠性的作用，仍不证明开放式代码或长程 Agent 都会获得同样效果。[附录 B.4.1、Figure 4](https://arxiv.org/html/2609.33180v2)

### 与今天主读一起看，要追问哪几件事

**以下是阅读与工程建议。** 看自动改程序、写记忆或改训练流程的系统时，先追踪评测反馈走向：谁能看分数，谁据此提出下一版，最终审计数据有没有再进入调试？开发数据可以反复用来找方向，但不能仅因另一批题从未直接显示给 Agent，就把反复查询它们当成独立验证。 例如，AIDE² 的外层会看到选拔成绩；它没有直接满足 REUSE 的“只回传接受决定”限制，不能把这里的统计保证套到主读实验上。

精读顺序是 §2.1 的假设、Algorithm 1、Table 1，再读附录 B 的信息表和消融；统计推导可留到需要实现时。与 AIDE² 配对的价值，是把“能提出有用改动”与“怎样可信地决定保留改动”接起来。REUSE 给出有条件的评测方案，尚未实证验证通用研究 Agent 的持续自我提升。[v2 全文](https://arxiv.org/html/2609.33180v2)
