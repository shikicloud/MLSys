# 答得更好了，模型究竟学到了什么？

准确率提高之后，我们还需要问：模型掌握了什么新东西，又有哪些变化只是让已有能力更容易发挥？今天主读 10 月的 token cue 研究，从固定回答开头两个 token 的实验，一直追到修改训练数据的因果对照。两篇选读分别检查混合推理模型的模式切换，以及 RL 与监督微调怎样改变内部特征。三篇都重视对照实验，但研究对象和结论范围不同；不能把某组结果外推成所有强化学习都没有学到新能力。先读主读的具体例子，表征与干预部分可以第二遍再看。

每天推荐 1 篇主读与 2–4 篇选读，覆盖 LLM Inference、RL Infra、Post-Training、RSI（递归自我改进），以及推理计算、Agent 学习与记忆、数据评估和模型架构。经典与前沿并行，按主题逐步展开；不要求与当前工作直接相关。候选不等于已读，无需一天读完。

## 主读 · Base Models Can Reason By Taking a Cue From Training Data

**年份 / 发表信息：** 2026 · arXiv 2026 · MIT / UC Berkeley / UW / Ai2 · v1 2026-10-05 · [原文](<https://arxiv.org/abs/2610.06851v1>)

**阅读建议：** 值得精读。优先看 Figure 1–5 和 §2–3，再用 Table 6、Table 16 与 Appendix B/F 核对采样和数据干预条件。最重要的不是记住一个好用的词，而是学习作者怎样检验“能力已经存在，但默认没有用出来”这个解释。

### 同一道题，只替模型写好开头，后面的解法就变了

论文展示了一道题：834 名学生上音乐课，占全校学生的三分之二，学校共有多少人？正确计算是 834 × 3 / 2 = 1251。对同一个 Olmo-3-7B 基础模型，作者先填入不同的回答开头，再让它自己续写。以 Answer 开头的一次回答直接给出错误的 1002；以 Okay 开头的另一条回答列出关系、算出 1251，还检查了计算。这是论文中的具体样例，不是每次生成都会重复的结果。

这里没有把正确答案塞进开头，也没有在两次生成之间训练模型。干预只是预先写入极短的回答前缀，称为 prefill，即预填充。它让我们能问一个更具体的问题：模型原本不会求解，还是在默认生成时更容易选择另一种回答方式？单个例子不能回答这个问题，所以论文随后做了跨题评测、RL 对照和训练数据干预。

本文精读的是 2026 年 10 月 5 日发布的 v1，作者 Sophie L. Wang、Amil Dravid 等来自 MIT、UC Berkeley、University of Washington 与 Allen Institute for AI。论文采用 CC BY 4.0。它的新意主要在后面的对照链条：不只找到一个有效提示，还回到训练数据检验它为何有效。[论文 v1 与 Figure 1](https://arxiv.org/pdf/2610.06851v1) · [作者项目页](https://www.sophielwang.com/cues)

### 开头出现的概率，与给定开头后会怎么写，是两回事

Olmo 的有效前缀写作 `.\n\nOkay`：其中 `\n` 表示换行，不是要输入反斜杠和字母 n。对该模型的分词器，句点加两个换行是一枚 token，Okay 是另一枚。Token 是模型处理的文本单位，不一定等于一个单词。作者把这种能影响后续行为的短前缀称为 token cue，本文称为“开头线索”。

给定一道题，一条完整回答的概率可以拆成 `开头的概率 × 给定开头后续写的概率`。两项影响不同：模型可能很少自己写出某个开头，但一旦收到它，就能继续写出不错的解法。强制预填充跳过了第一项的选择过程，因此可以单独观察后面的续写能力；它并没有直接改变模型权重。

“基础模型”也不意味着没有看过推理文本。本文的 Olmo 等模型在预训练和后续的中期训练中已经接触到这类数据，尚未接受所比较的 RL 更新。评测的原始提示模板本身也要求逐步求解。因此准确的说法是：保持原有题目和指令，只改变回答开头，再观察额外效果。[§2 与 Appendix B.2](https://arxiv.org/html/2610.06851v1#S2)

### 怎样找线索：用训练题上的答案一致性，而不是测试题正确率

作者先取 30 道 MATH 训练题，用 beam search 搜索模型本来较可能生成的开头。这里的 beam search 只是每一步保留一组概率较高的候选；宽度为 20，深度为两个 token，最后得到 20 个短开头。随后对每个开头、每道题各生成 16 条完整回答，比较最终答案是否集中。

选择标准叫答案熵：同一道题的 16 条回答越集中在少数答案上，熵越低。研究者选平均熵最低的候选，不需要查询标准答案；同时过滤掉答案缺失率明显恶化的候选，防止“总是不输出答案”显得很一致。选定后，同一模型和提示模板使用同一个开头，跨所有评测题与基准保持不变。[§2.1](https://arxiv.org/html/2610.06851v1#S2.SS1)

这里的“无答案标签”不等于没有成本。仅上述候选评分就需要 20 × 30 × 16 = 9,600 次续写，这是由设置算出的数量，还未计候选搜索。答案一致也可能是大家都答错，所以它是本实验验证过的一种选择指标，不是正确性的保证。新数据分布下仍需要独立评测，不能在测试集反复挑到一个最好的词再报告收益。

### 收益有多大：先分清单次成功率与多次尝试

MATH-500 是包含 500 道数学题的测试集。Table 6 中，Olmo-3-7B 在固定 RL-Zero 提示下，从不预填充时的 42.2% 提升到 77.9%；Qwen3-14B 在自己的 boxed 提示下，从 72.2% 提升到 86.6%，使用的开头是带前导空格的 ` Alright,`。这些是各自模型内的对照，不是把两种提示混在一起比较模型强弱。

指标 pass@1 表示一次随机生成答对的概率。作者每题采样 32 次来估计它，而不是从 32 次里选一条对的就算成功。后者属于另一类多次尝试指标。默认采样温度为 0.6、top-p 为 0.95、最多生成 31,744 token；温度和 top-p 控制随机采样方式，token 上限控制最长回答。误差棒反映采样轮次的变化，不代表多次独立训练的差异。[Appendix B.1 与 Table 6](https://arxiv.org/html/2610.06851v1#A2.SS1)

同一线索也被原样用于其他数学题和 HumanEval 代码测试。Olmo 的数学与代码成绩都改善；Qwen 的代码成绩则仍接近本来就较高的基线，并非所有任务都有同样收益。Olmo 在 MATH-500 的 pass@16（16 次尝试至少一次答对的概率）只从 94.0% 变为 95.4%，说明单次成功率的大幅提升，不应直接说成“可解题范围扩大了一倍”。

### RL 改变了什么：先看同样的前文，再比较下一步

若两个模型前面已经写出不同内容，后面的差异可能只是由不同上下文造成。作者因此把完全相同的 token 历史分别送给基础模型和 RL 模型，逐位置比较下一 token 的概率分布。用来量化分布差异的指标是 KL divergence；这里不必先掌握公式，只需知道它用于检查两套预测有多不同。

在所测轨迹上，最大的分布差异集中在最开始的两个位置，后面明显减小。Olmo 的目标开头概率从 0.14 升到 0.65，Qwen 从 0.04 升到 0.58。作者还让基础模型接着 RL 模型写出的开头继续生成，恢复了接近 RL 的成绩。这个交换实验的切换点是首个空行之后再过两个 token，不能误写成严格只交换最前面两个 token。[§2.3 与 Appendix D.3](https://arxiv.org/html/2610.06851v1#S2.SS3)

另一组实验比较普通 RL 与始终强制给定线索的 RL。它使用 GRPO：同题生成多份回答，以正确与否的奖励相对组内平均值来更新。作者用 LoRA 训练 300 步，即只学习一组紧凑的权重增量，训练回答上限为 4,096 token；这与前面的评测预算不同。强制线索在训练前就获得很高成绩，后续改善较少，支持“这些运行中相当一部分收益来自更常进入已有续写方式”，而非证明所有 RL 只学了开头。

### 会不会只是写得更长，碰巧多算了几步？

这是必须排除的解释。Olmo 加线索后，平均回答确实从约 4,800 token 增至 6,700 token。但其他候选开头有的生成长度约为有效线索的两倍，正确率却低于不加线索。多输出文字本身不足以解释为什么某些开头有效。

作者进一步把已经生成的回答截到相同 token 数，再检查截断范围内是否已有可提取的正确答案。Olmo 的有效线索从约 1,000 token 的截断点起仍优于无开头线索的条件。这能支持“收益不完全由长度增加解释”，但不是让模型提前知道预算后重新作答，也不是测量相同 GPU 时间下的服务效果。[§2.4 与 Appendix E.1](https://arxiv.org/html/2610.06851v1#S2.SS4)

这一控制也有边界：Qwen3-14B 在很小的截断预算下，带线索反而可能更差。若线索使模型先写很长的推理，而使用场景要求极短回答，它未必合适。因此，判断一种生成方式是否更好，应连同答案正确率、输出长度和实际延迟一起看；最后一项是面向应用的评估建议，并非论文已测的结果。

### 真正的因果检验：把训练中的 Okay 改成 Chicken

作者发现 Olmo 中期训练数据里，83% 的合成推理轨迹以 Okay 开头。但仅有这个统计，还不能确认它造成了效果。于是研究者从同一份预训练 checkpoint 重启中期训练，保持训练配方、数据顺序和随机种子相同，只改数据里的词。中期训练是预训练后继续吸收特定数据混合的阶段，与按答题奖励进行的 RL 不同。

第一组用原文，第二组把混合数据中完整单词 Okay/okay 替换成 Chicken/chicken，称为 rename。两组都训练 100 亿 token。在 MATH-500、7,168 token 回答上限下，Chicken 线索的 pass@1 从 2.4% 变为 37.2%，接近改名后 Okay 的 38.3%。这些数字属于较短的重训实验，不能接在前面已发布基础模型的 77.9% 后面当作一次连续变化。[Appendix F.1 与 Table 16](https://arxiv.org/html/2610.06851v1#A6.SS1)

这说明 Chicken 无须在自然语言中表达“认真思考”，也能在特定上下文里获得推理线索的作用。关键是训练时它反复出现在什么文本之前。不过，改名后无条件答题成绩也从 13.8% 升到 23.3%，所以不能宣称这次数据改动只影响了一个词、其他行为完全不变；因果证据来自整组有明确对照的行为变化。

### 删掉旧关联还不够：让 Okay 转而表示“下面是一道新题”

改名实验有一个很有价值的结果：即使这批中期训练文本不再出现 Okay，强行填入 Okay 仍能引出推理。它自然出现的概率大幅降低，但给定它之后的续写功能保留下来。作者指出，这个开头在更早的预训练 checkpoint 上就已有效；早期关联可能解释了为何作用没有被简单删词抹去。

第三组从 rename 数据继续修改，把短问答数据中段首的 Question: 换成 Okay,，称为 redirect。现在 Okay 更常接着“一个问题是什么”，而非“这道题如何求解”。训练后，Okay 线索的 MATH-500 成绩降至 0.2%，Chicken 仍为 40.1%，无前缀条件为 26.7%。这不是模型整体失去了解题能力，而是某个开头与后续行为的关系发生变化。[§3.1 与 Table 16](https://arxiv.org/html/2610.06851v1#S3.SS1)

补充实验在 SmolLM3 上观察到类似模式；另一次完整的 1,000 亿 token Olmo 改名实验中，Chicken 从未改名对照的 18.2% 达到 76.9%。后者是另一训练预算，不能与 100 亿实验混用。这些复验增强了数据关联解释，但两个干预模型的训练混合都含合成推理文本，尚不能据此保证任意预训练数据与模型都会出现同样效应。

### 模型内部的证据支持什么，又没有证明什么？

隐藏状态是模型在各层处理文本时产生的数值向量。作者取 Olmo 第 24 层的回答向量，与训练文档经过同层所得的向量比较，寻找最相似的十个邻居，再看这些邻居更多来自哪类文本。有效线索之后的状态，更接近合成推理轨迹中的状态；Answer 等开头则更接近短问答文本。

这是生成过程与训练文本类型之间的相关证据，不是模型在运行时检索了这些文档，也不是已经找到一个控制推理的独立神经电路。论文自己的反例很重要：某个开头也能使状态接近“推理相关”文本，但模型只重述任务和列步骤，没有算出答案。风格像推理，不等于推理正确。[§3.2](https://arxiv.org/html/2610.06851v1#S3.SS2)

位置同样影响结果。研究者在回答前面的一两个段落插入 Okay 时，状态相似性的变化能保持较久，正确率也提高；更晚插入时，变化短暂，成绩甚至低于基线。它说明线索的效果依赖已经积累的上下文，不是随时插入一个词就能让模型重新正确思考。

### 应带走的结论，以及精读时最该核对的地方

最有用的结论是把两个问题分开：模型在适当条件下能做什么，以及默认有多大概率采用那种行为。本文通过回答前缀、RL 对照、数据改名与重定向把这一区别落实成实验。它为所测设置提供了具体解释，不能替所有 R1 之后的复杂后训练作结论；作者明确限制在直接从基础模型开始的 RL-Zero 风格比较。

其他边界也应保留：测试过的 Llama-3.1-8B 开头没有找到有效线索，数学与代码迁移并不均匀，而且短重训实验的 AIME 成绩仍很低。表格中的采样误差也不能代替多训练种子的可靠性检验。因此这篇值得读的原因是干预设计清楚，而不是它证明“两枚 token 可以取代现代 RL”。[§6](https://arxiv.org/html/2610.06851v1#S6)

精读可按 Figure 1 的例子、§2.1 的选择过程、§2.3 的 RL 对照、§3.1 的三组数据干预、§3.2 的内部证据这个顺序。复现实验则要固定模型版本、分词器、提示模板、前缀字节、采样设置和评测预算，并把选线索的题与评测题分开；这是从实验设计提炼的建议。官方代码已公开，但本文没有重新运行模型实验。[官方代码](https://github.com/sophicle/cues)

## 选读 · The Thinking Leakage in Reinforcement Learning for LLMs

**年份 / 发表信息：** 2026 · arXiv preprint · v1 · 2026-10-09 · [原文](<https://arxiv.org/abs/2610.14270v1>)

**阅读建议：** 值得精读 §5.2 的双向激活交换，接着看 §5.3 区分内部机制证据与解题效果；和今天主读一起理解模型能力如何被调用。

### 1. 没有展开思考，不等于模型不会思考

想象同一道数学题交给同一个模型：一条路径先写推导，再给答案；另一条路径直接回答。这是教学说明。论文研究的 Qwen3 两种模式共用权重，即模型保存的参数；区别在聊天模板。THINK 允许生成 &lt;think&gt; 内的推导，NO-THINK 则在输入末尾预先放入空思考块：&lt;think&gt; 后换两行，接着放 &lt;/think&gt; 并再换两行，表示这部分已经结束。这里的混合推理指同一模型支持两种模式，与前几天 attention/SSM 混合架构的“混合”含义不同。“原模型”是已发布的推理模型，并非未经后训练的纯预训练模型。[§3：模式与模板](https://arxiv.org/html/2610.14270v1#S3)。

如果对第二条路径训练后，模型答得更好却又写起长推导，至少存在两种解释：学到了新解法，或者更愿意调用原来已有的推理方式。作者把后一种现象称为 thinking leakage。这里的 leakage 指模式间行为重新出现，不是测试答案泄漏。区分这两种解释，需要比较原模型的 THINK 模式，并干预内部计算。[§1：研究问题](https://arxiv.org/html/2610.14270v1#S1)。

### 2. 训练改什么，评测又允许做多少工作

作者用 DAPO-Math-17k 训练 Qwen3-1.7B、4B、8B，始终使用 NO-THINK 模板。每步取 256 道题，每题生成 5 个回答，温度为 1。GRPO 根据同题回答的奖励差异调整生成概率；训练的是所有线性层上的 rank-64 LoRA，即给权重附加一组受低秩结构约束、可学习的更新，而非直接训练全部原始参数。[§3：训练设置](https://arxiv.org/html/2610.14270v1#S3)。

评测使用 AIME 2022–2024 的 I、II 卷共 90 题，按最后一个 boxed 答案判分，缺失则算错。两模式生成上限都是 32,768 token，Fig.1 每题采样两次、温度为 1。训练上限则不同：8B 为 8k，另两个规模为 16k。相同评测上限只意味着都允许写这么长，并不保证实际生成量相同。[§3](https://arxiv.org/html/2610.14270v1#S3)、[附录 H](https://arxiv.org/html/2610.14270v1#A8)。

### 3. 先观察：变准的同时，也变得更像 THINK

Fig.1 中，8B 的 NO-THINK 准确率约从 17% 升至 43%，平均回答由 2.7k 增至 7.2k token；原模型 THINK 准确率约 74%。作者还把同一回答分别接在两种模板后，让原模型计算文本出现的概率。训练后的回答比原来的 NO-THINK 回答更偏向 THINK 模板，在两两比较中胜出约 94%；这不是 94% 的解题准确率，也不是人工评价。[§4、Fig.1](https://arxiv.org/html/2610.14270v1#S4)。

模型内部每层计算出的临时向量叫激活。作者固定回答文本，只更换模板或模型权重，发现 RL 后的激活也向原模型 THINK 状态移动。这样排除了“只是读到了不同文字”的解释，但相关性仍不够：新学到的方法也可能产生相似激活。因此，后面三组实验主动改变权重或激活，再看行为怎样变化。[§3 的测量定义](https://arxiv.org/html/2610.14270v1#S3)、[§5](https://arxiv.org/html/2610.14270v1#S5)。

### 4. 放大权重更新：看训练方向通向哪里

把训练前权重记为 W₀，训练改变的部分记为 ΔW。作者不追加训练，而是测试 W₀＋cΔW：相当于沿已有更新方向走得更远。8B 第 67 步的更新放大至 c＝3 时，NO-THINK 准确率达到 72.2%，约 50.6% 回答自行写出 &lt;/think&gt;，尽管模板已经关闭过思考块。这比仅统计“wait”等词，更具体地指向原有模式行为重新出现。[§5.1](https://arxiv.org/html/2610.14270v1#S5.SS1)、[附录 B、Table 5](https://arxiv.org/html/2610.14270v1#A2)。

但系数是在同一批 90 题上探索的，每题两次采样；这不是在新测试集确认的最佳设置。更大系数还会让回答过长、触及上限。所测系数没有超过原 THINK 的约 74%，只能描述这次实验，不能把 74% 当作理论能力上限，也不能说放大权重总比继续训练有效。[附录 B](https://arxiv.org/html/2610.14270v1#A2)。

### 5. 交换内部数值：增益能否被拿走或移过去

更强的检验是只交换一小部分激活。作者用原模型和 128 道训练题，找出每层与两种模式差异有关的 8 个方向，合起来称为 8 维子空间。生成时，两个模型都使用 NO-THINK 模板，读取完全相同的 token；在第 1–35 层、所有位置，用来源模型的这部分数值替换目标模型对应部分，其余分量保留。维度和层范围预先固定，没有用 AIME 成绩挑选。[§5.2](https://arxiv.org/html/2610.14270v1#S5.SS2)、[附录 C](https://arxiv.org/html/2610.14270v1#A3)。

这组独立采样实验仍是 8B 第 67 步、90 题各两次、32k 上限。未干预的原模型准确率为 18.9%，RL 模型为 41.1%，差值 22.2 个百分点。把原模型的 THINK 子空间分量换回 RL 模型后，准确率降到 24.4%，去掉约 75% 的这次增益；反向交换让原模型升至 30.0%，转移约 50% 的增益。这里的百分比不是全部推理能力的比例。[§5.2、Fig.3](https://arxiv.org/html/2610.14270v1#S5.SS2)、[附录 C、Table 6](https://arxiv.org/html/2610.14270v1#A3)。

同样交换 8 维、但选原激活变化最大的 PCA 方向，只移除约 22% 的增益，反向转移约 25%；随机方向影响更小。这说明不是随便扰动一块内部数值都会产生同样效果。不过，干预也改变了回答长度，且并未移除全部增益，因此它支持特定模式机制的重要作用，不等于完整解释 RL 的所有改变。[§5.2](https://arxiv.org/html/2610.14270v1#S5.SS2)。

### 6. 哪些注意力头把模板信号传进回答

注意力头可以理解为模型读取前文信息的一条计算通道。作者找到特别关注空 think 块的头，再禁止它们读取那几个模板 token，其他输入不变。8B 中，对最关注该块的 5% 头做这项干预，下一 token 分布与 THINK 的 KL 差异减少 72%；同数量随机头的五次抽取平均只减少 3%。KL 在这里衡量两个概率分布的差异，72% 不是准确率。[§5.3、Table 1](https://arxiv.org/html/2610.14270v1#S5.SS3)。

这些实验让模型读取固定回答的前 2,048 token，并未自由生成新答案。单头交换进一步发现，最能传递 RL 后激活变化的头，也高度关注空 think 块；用 30 条文本排名后，在另外 60 条检查。它补上“模板通过哪些通道影响内部状态”的证据，但不能据此声称删掉这些头就能提升解题率，单头影响也不能直接相加。[§5.3、Table 2](https://arxiv.org/html/2610.14270v1#S5.SS3)、[附录 E](https://arxiv.org/html/2610.14270v1#A5)。

### 7. 奖励为什么可能把模型推向这种行为

GRPO 的 advantage 表示一个回答比同组回答好多少，并影响更新力度。比如五个回答只有一个答对时，这个正确回答比“四个都答对”时得到更强的正向信号。作者另取 256 道训练题、每题生成 20 个回答，观察到受奖励的回答更像 THINK；再从初始模型计算一次受控梯度更新，内部状态也向 THINK 移动。这提供一种可能原因，并非所有 GRPO 训练必然如此的证明。[§6](https://arxiv.org/html/2610.14270v1#S6)、[附录 G](https://arxiv.org/html/2610.14270v1#A7)。

最值得带回评测工作的结论是：报告提升时，应同时给模式模板、原 THINK 基线、生成长度及干预证据。这里研究的是三个 Qwen3 规模的数学任务，核心准确率交换只做了 8B；原文未报告多训练种子的完整重复与准确率置信区间。它不能推出“RL 从不学新能力”。本文为 Wenxuan Zhu 等 KAUST 与上海交大研究者于 2026-10-09 发布的预印本；本笔记依据 v1，以中文解释和英文转述改写，原作采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。建议优先读 [§5.2](https://arxiv.org/html/2610.14270v1#S5.SS2) 与[附录 C](https://arxiv.org/html/2610.14270v1#A3)，再读 §5.3、§6。

## 选读 · Why Does Reinforcement Learning Generalize? A Feature-Level Mechanistic Study of Post-Training in Large Language Models

**年份 / 发表信息：** 2026 · ACL 2026 · Long Papers · July 2026 · [原文](<https://aclanthology.org/2026.acl-long.1808/>)

**阅读建议：** 值得精读 §3.2 与 §7 的特征筛选和干预，再用附录 A、B.4 核对训练差异与测试范围；不必先啃全部特征分布图。

### 1. 数学训练之后，为什么科学题也会变好

先看一个教学情境：模型只用数学题继续训练，之后却更容易答对“哪种材料导电”这样的科学选择题。改善可能来自更好地调用原有知识，也可能涉及新的内部计算。仅看最终答案，分不清这些解释。这篇论文进一步打开模型，寻找参与改变答案的内部特征。这里的泛化指超出本次数学后训练领域的表现，不等于证明测试知识从未出现在预训练中。

今天主读关注提示中的训练数据线索如何引出 base 的表现；这篇则实际更新权重，再动手修改模型内部活动，观察答案是否随之改变。两者可以共同帮助判断“原来就有的能力怎样被调用”，但都不能单独裁定所有 RL 只是在重排旧答案，或一定创造了全新的能力。

### 2. 题目相同，两种训练看到的答案却不同

作者分别从 Qwen3-4B-Base 和 Qwen2.5-7B 出发，使用同一批约 47K 数学题。SFT，即监督微调，学习 Qwen3-32B-Instruct 写出的、最终答案正确的完整推理过程。RL 使用 GRPO：每题让模型自己生成 8 份回答，根据最终答案对错给奖励，再比较同组回答来更新模型；它没有看到教师的中间解题步骤。

两者都更新全部参数，训练一轮后评测最后的权重，但并非等计算预算实验。RL 学习率是 1e−6，SFT 是 5e−5；RL 的生成上限为 16K token。训练使用 H100/H200 GPU。相同起点与题源减少了一些差异，却没有固定监督文本、生成量和优化设置，不能把观察结果归结为一个孤立变量。[附录 A.2–A.3](https://aclanthology.org/2026.acl-long.1808.pdf#page=13)。

完整评测的 Table 1 中，Qwen3 在 SciQ 科学问答的正确率为 base 78.5%、SFT 51.8%、RL 89.5%。不过，Qwen2.5 在 CommonsenseQA 上从 base 的 77.6% 变成 RL 的 76.1%。这些数值同时说明该配方有跨领域收益，也提醒我们不要把“RL 比这里的 SFT 好”读成“RL 每项都比原模型好”。

### 3. 先给不同模型建立同一张坐标纸

模型处理一个 token 时，会在中间层留下一个数值向量，称为激活。直接比较向量的第几个数，很难知道它代表什么。作者训练一个 Sparse Crosscoder：把不同模型的激活一起编码成一组共同的数值，再用各模型自己的解码器重建原向量。训练要求重建接近原值，同时让每次只有少量数值活跃；这些共同坐标就是这里的稀疏特征，并非已经命名好的“逻辑神经元”。

用于训练这个分析工具的语料另有 4 亿 token，一半来自 OpenThoughts-114K，一半来自 RedPajama 通用文本；它们不是前述 47K 题的 RL 训练输入。工具包含 32,768 个特征，重建各模型中间层的激活。比较 base、SFT、RL 时，作者还让三者共享同一个 Crosscoder，避免把独立工具里碰巧同号的特征误认成同一种东西。

图中的 NRN、MAS 根据解码器向量的大小，衡量一个特征在重建不同模型时更偏向谁。作者观察到该配方的 RL 表征较多保留与 base 共享的成分，SFT 的模型专属成分更明显。这是分析工具中的相对分布，不是“保留了百分之多少推理能力”，也不意味着 RL 没有产生新特征。[§3.1、§5.1、§6](https://aclanthology.org/2026.acl-long.1808.pdf#page=3)。

### 4. 从答题差异中找候选特征

接着，作者在五个通用问答任务中，分别挑出 base 答错、RL 答对的题。对这些题，取最后一个 token 位置的激活，通过各自编码分支得到特征值，计算每个特征在 RL 中比 base 平均高多少。这一步是在找与改进一起出现的候选变化，还没有证明这些变化造成了改进。

每个任务保留分数超过本任务最大值 20% 的特征，再取五个任务的交集，得到 Qwen3 的 50 个、Qwen2.5 的 16 个候选特征。交集让候选不只来自某一类题，但选题本身已经利用了模型答对与否的信息。这一点会决定下一节的数字应当怎样读。[§3.2、§7](https://aclanthology.org/2026.acl-long.1808.pdf#page=4)。

### 5. 真正改动这些特征后，答案会不会变

作者在推理时做两种操作：把 RL 模型的候选特征值置零；把 base 的对应值设为 3.0。后者是设置数值，并非把原值乘以三。这些操作不再训练模型权重，而是直接改变中间激活，测试候选特征是否确实参与产生答案。置零后 RL 表现下降，设置后 base 表现改善，提供了比“数值一起变大”更强的干预证据。

最容易误读的是分母：Table 2–3 仍在“base 错、RL 对”的题集上评测。例如 Qwen3 的 OpenBookQA 项为 −46.2，表示这些原本由 RL 答对的筛选题中，约 46.2% 在置零后答错；不是完整 OpenBookQA 降低 46.2 个百分点。主实验也没有明确说明找特征与验证干预使用了分离的题集，所以不应把它当成新测试集上的无偏性能估计。

### 6. 换任务仍有效，结论又能走多远

附录 B.4 把同一批特征用于 LogiQA 逻辑题和 PIQA 物理常识题，这两项没有参与特征筛选，干预仍影响答题。但 Table 4–5 依然只评测各任务里 base 错、RL 对的子集。“未见任务”指没有参与找特征，不是证明模型预训练时从未见过这些知识，也不是报告完整任务的收益。[附录 B.4](https://aclanthology.org/2026.acl-long.1808.pdf#page=15)。

因此，较稳妥的结论是：在这些模型、训练配方和筛选题中，一小组可被共同表示的特征参与了答题变化。Crosscoder 只是近似重建一个中间层，不能覆盖全部计算；改动特征能改变答案，也不自动证明它就是某个人类推理概念。若要推广为训练方法，还需要独立题集、其他配方及完整性能评测。

### 7. 怎样精读，怎样带回自己的实验

建议先读 Table 1 与附录 A，弄清真实训练差异；再读 §3.2 的选题和选特征步骤，最后读 §7、附录 B.4 的干预结果。理解这条证据链后，再补 §3.1 的公式。对系统实验的启发是保留两份报告：完整评测回答“整体有没有变好”，筛选题的诊断回答“哪些变化可能参与其中”。这是本文引出的实验建议，不是论文已经验证的部署方案。
