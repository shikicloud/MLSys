- [INGEST] arXiv:2602.13692 "ThunderAgent: A Simple, Fast and Program-Aware Agentic Inference System" (Kang*, Li*, Yang*, Xu*, Chen, Wang, Chen, Krishna, Xu, Arora; Georgia Tech + CMU + UIUC + Together AI; ICML 2026 **Spotlight (top 2.2%)**; v1 2026-02-14, v2 2026-03-10) — paper review at [[thunderagent]] in `wiki/llm-serving-for-agents/`. **Critical backfill — the system layer [[mori|MORI]] runs on top of**, and the **contemporary competitor to [[continuum|Continuum]] that beats it on all 6 of its own benchmarks** (SWEAgent, OpenHands(code), ToolOrchestra(HLE), ScienceAgent × GLM-4.6 / Qwen3-235B / Qwen3-8B). Core thesis: **abstract multi-turn workflows as `agentic programs`** $P = \langle ID, c, \mathcal{T}, \mathcal{L}, \tau, s \rangle$ and schedule at program granularity rather than per-request. Three components: (1) **Periodic thrashing monitor** at $\Delta t = 5$ s evaluating $C_{\text{total}} < \sum_p c_p$; Pause/Restore primitives sort by $1/c_P + \mathbb{1}(\tau)$ giving shortest-context-first eviction (formalized by **Lemma 4.1**: $\text{Cost}_{\text{recompute}} \propto c_i^2$, so greedy shortest-first is optimal); **time-decay function** $f(t) = 2^{-t}$ on Acting programs (proven optimal under memoryless tool durations, Appendix E.1) — the reactive counterpart to Continuum's predictive TTL. (2) **Global program-aware waiting queue** across DP nodes — paused KV is node-agnostic so any backend with capacity can restore; bounds $\text{Cost}_{\text{unused}} < c_{\min} \cdot \Delta t$ vs the 51% peak imbalance baseline vLLM+SGLang routers suffer on 90-min OpenHands RL rollout. (3) **Tool resource management**: hook-based GC tears down sandboxes/network ports on $s = \text{Terminated}$ (active disk near-constant vs linear-growth baselines exceeding 2 TB after ~250 workflows); async env preparation overlaps Docker pull / dep install with LLM phase (hides 29.9-47.2 s setup latency). **Headline numbers**: serving throughput **1.48–3.58× vs vLLM**; **1.17-3.31× vs Continuum on all 6 benchmarks**, with **Continuum losing to vLLM (0.65×)** on ToolOrchestra-HLE stochastic tool workload while ThunderAgent wins (1.48× vs vLLM); **RL rollout 1.79-3.92× vs vLLM+SGLang Gateway SOTA**; KV cache hit rate ~100% on predictable workloads (Continuum drops to ~60% under high concurrency); up to **4.2× disk savings**; baseline thrashing impact 7.14× E2E latency blowup. **Cost decomposition** $\text{Cost}_{\text{total}} \approx \text{Cost}_{\text{decode}} + \text{Cost}_{\text{prefill}} + \text{Cost}_{\text{recompute}} + \text{Cost}_{\text{unused}} + \text{Cost}_{\text{caching}}$ via Space-Time Product metric (Eq. 2). **API**: OpenAI-compatible with one extra `program_id` parameter — trivial client integration. **Code**: [ThunderAgent-org/ThunderAgent](https://github.com/ThunderAgent-org/ThunderAgent) (MIT, vLLM + SGLang backends). **Models tested**: GLM-4.6 (355B MoE, FP8, TP=8), Qwen3-235B, Qwen3-8B; **hardware**: 8×H100, RTX 5090. **Hyperparameters**: $\Delta t = 5$ s, $f(t) = 2^{-t}$, $\lambda_{\max} = \lambda_{\min} = 1.0$. **Lineage placement**: Generation 1 (vLLM/SGLang request-level, agent-oblivious) → Generation 2 ([[infercept|InferCept]] per-request Discard/Preserve/Swap) → Generation 3a ([[continuum|Continuum]] per-program **predictive** TTL) → **Generation 3b (ThunderAgent per-program reactive thrashing monitor)** → Generation 4 ([[mori|MORI]] two-tier GPU+CPU on top of ThunderAgent). The Continuum-vs-ThunderAgent split is **predictive vs reactive** — predictive wins when tool durations are well-modeled; reactive wins when stochastic. Limitations: single-cluster only (no geo-distribution like [[prfaas|PrFaaS]]); no SLO/priority/fairness; time-decay $f(t) = 2^{-t}$ hard-coded; Δt fixed; hook-based GC requires well-behaved tools; no explicit comparison to InferCept; workload coverage misses GUI/multimodal/HITL chatbot. - [INGEST] arXiv:2402.01869 "InferCept: Efficient Intercept Support for Augmented Large Language Model Inference" (Abhyankar*, He*, Srivatsa, Hao Zhang, Yiying Zhang; UCSD WukLab; ICML 2024, PMLR 235; v1 2024-02-02, v2 2024-05-30) — paper review at [[infercept]] in `wiki/llm-serving-for-agents/`. **Backfilling the canonical agent-serving baseline** — the predecessor that both [[continuum|Continuum]] and [[mori|MORI]] cite as the first system to address KV-cache management during agent tool calls / human responses. Core thesis: **a tool call / human response is an *interception* (not an end-of-request)** and the KV cache during it is *temporarily unused context* worth managing as a first-class resource. **Four contributions**: (1) Closed-form **waste equations** for the three actions — $\text{WasteDiscard}_i^j = T_{fwd}(C_i^j) \times C_i^j \times M + T_{fwd}(C_i^j) \times C_{other} \times M$, $\text{WastePreserve}_i^j = T_{INT}^j \times C_i \times M$, $\text{WasteSwap}_i^j = 2 \times T_{swap}(C_i^j) \times C_{batch} \times M$ — plus a fourth, **WasteChunkD**, for chunked recomputation; rule $\text{Waste}_i^j = \min(\text{WastePreserve}_i^j, \text{WasteChunkD}_i^j)$. (2) **Swap pipelining and chunking** — overlap CPU↔GPU PCIe with forward kernels at layer granularity, budgeted swap-out under PCIe + free-CPU constraints; eliminates 96% of Swap waste. (3) **Recomputation chunking at the GPU saturation point S** (offline-profiled query-token count beyond which iteration time grows monotonically) — chunked recompute fills decode's spare GPU cores; halves Discard waste. (4) **Min-waste scheduling** — descending-sort intercepted requests by `min(WastePreserve, WasteChunkD)`, assign to swap (within PCIe-bandwidth budget) / preserve / discard; three queues (running / swap / waiting), FCFS by original arrival preserved across interception. Plus a **dynamic interception-duration estimator** $\hat{T}_{INT} = t_{now} - t_{call}$ achieving 93% of oracle. **Headline numbers**: 1.6×–2× throughput improvement, 2× more completed reqs/sec; 6B → 1.6× higher arrival rate at same normalized latency, 1.9×–5.7× lower normalized latency; 13B-TP2 → 1.6×–10× lower normalized latency; **70B-TP4 → 1.3×–12× lower normalized latency, 2.4× higher load at same TTFT**; GPU memory waste **~25% → 0.69%** (eliminates >60% of recompute waste, 96% of swap waste). Six augmentation taxonomy (Math/QA/VE/Chatbot/Image/TTS, paper Table 1) becomes the standard agent-workload benchmark used in subsequent work. **Built on vLLM**; uses PagedAttention; no custom CUDA. **Limitations later targeted**: (a) waste model uses *reload cost only* — no per-turn queueing-delay penalty for returning requests → Continuum's `OutOfOrderCost`; (b) no retention bound — a hung tool call holds KV indefinitely → Continuum's TTL expiry; (c) single-tier GPU vs binary CPU swap → MORI's two-tier idleness metric; (d) interception is binary per-request, no partial pinning of recent vs ancient KV blocks → Pie's programmable cache; (e) workload-specific tuning (S, swap budgets, preserve thresholds); (f) no multi-tenant SLO discussion. Code at https://github.com/WukLab/InferCept (vLLM fork). - [INGEST] arXiv:2606.00866 "Idleness is Relative: Exploiting Tool-Call Idle Windows for Offloading in Agentic Systems with MORI" (Xia, Li, Li, Chen, Kang, Qiao, Xu, Stoica; UC Berkeley + Renmin University of China + Stanford + Georgia Tech; 2026-05-30) — paper review at [[mori]] in `wiki/llm-serving-for-agents/`. **Direct successor to [[continuum|Continuum]] by same first author Hanchen Li (UC Berkeley)**. Where Continuum was single-tier (GPU HBM only) with TTL pinning, **MORI is two-tier (GPU + CPU DRAM)** with a continuous **idleness metric** $\iota = T_{acting}^{(k)}/(T_{reasoning}^{(k)}+T_{acting}^{(k)})$ over k=5 inference/tool-call cycles. Three failure modes Continuum hit: (1) tool-call duration variance **3 orders of magnitude** in Claude Code traces (P50=1,096ms, P90=2,034ms, P99=19,980ms, P99.95=83,626ms over n=16,886); (2) binary busy/idle classification breaks when busy:idle program ratio mismatches GPU:CPU capacity ratio (H100 DGX 1:1.6, same node with 2TB DRAM 1:3.1); (3) CPU DRAM also finite — naive "offload everything idle" causes contention. **MORI design**: (a) **Idleness metric** windowed and excludes scheduler-imposed wait time, both responsive (busy→idle transition shows quickly) and outlier-robust (single anomalous tool call diluted by window); (b) **Three-tier queue**: GPU queue (HBM, busy programs, KV resident), CPU queue (DRAM, idle programs, KV offloaded with cache affinity), Waiting queue (KV discarded, full re-prefill needed); (c) **Sticky rebalancing** in 5s control loop — programs stay in tier until idleness mismatch + capacity boundary crossed; demotion ranks by idleness, prefers Acting over Reasoning (lazy demotion if only Reasoning), promotion uses Best-Fit-Decreasing bin packing with cache affinity; (d) **Typed offloading on inference engine** — scheduler propagates busy/idle/inactive label, engine LRU uses type as higher-priority sort key with reversed priorities between tiers (GPU evicts busy last, CPU evicts idle last). **Implementation**: ~3,300 lines Python on ThunderAgent + 500 lines on SGLang v0.5.10 HiCache. **Headline results** on real Claude Code SWE-bench Pro traces (claude-sonnet-4-6 high effort, 186 complete traces from 200 tasks, claude-sonnet-4-6, 80 concurrent programs): H200 80GB Qwen-2.5 7B 853 vs TA+O 667 tokens/s (+28%); B200 Llama-3.1 70B **213 vs 124 tokens/s (+71% — the load-bearing high-memory-pressure result)**; multi-replica DP=3 **54-79% higher throughput**; TTFT 18-43% lower average / up to 2.8× lower peak; 99%+ GPU utilization at 80 concurrent vs 59-76% for phase-oblivious. **Architectural progression** clear: Generation 1 (vLLM/SGLang LRU per-request, GPU only) → Generation 2 (Continuum TTL per-program, GPU only) → Generation 3 (MORI continuous idleness per-program, GPU + CPU) → Generation 4 (predicted: three-tier GPU/CPU/SSD with WAN-aware). Limitations: no code released; no head-to-head vs Continuum despite obvious comparison; only sequential ReAct flows (no parallel tool calls); only coding agent workload (Claude Code); k=5 window empirically chosen with no sensitivity analysis; no cold-start ramp analysis; tested up to 80 concurrent programs only; no fairness discussion; type-label propagation fragile under engine restart. Core mechanism: two-role decomposition (slow authoritative **Actor** + fast cheap **Speculator**) running k-way breadth speculation.
