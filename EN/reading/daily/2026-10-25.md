# How Models Use Images to Reason: Joint Generation, Re-reading, and Selective Access

Why can a drawn route and written moves each be correct yet contradict one another? The main reading, JUICE from October 20, explains how image and text can be generated together. CVRR examines whether answers really depend on visual latent states; ViMoD studies selective access to image details during long reasoning. These recent preprints address coordinated generation, necessary internal computation, and access to visual evidence. Start with the main reading’s maze example and explore the companions as interest permits.

Each digest recommends 1 main paper and 2–4 optional papers across LLM inference, RL infrastructure, post-training, RSI (recursive self-improvement), reasoning compute, agent learning and memory, data and evaluation, and model architecture. Explore foundations and current research by theme; a direct connection to current work is not required. A recommendation does not mean it has been read, and there is no need to finish everything in one day.

## Main reading · JUICE: Unified Multimodal Modeling in Pretrained Representation Spaces

**Year / publication：** 2026 · arXiv 2026 · NYU / Harvard / UIUC / Princeton / UPenn · v1 2026-10-20 · [Original source](<https://arxiv.org/abs/2610.28801v1>)

**Reading guidance：** Worth close reading: Figures 1–2 and Table 7, then Sections 3.2–3.5 and 4.3 and Appendices D.1–D.2.

### A puzzle: both answers are valid, so why does the pair fail?

Imagine a maze with two shortest routes. A model draws a blue path around the upper side but writes moves around the lower side. Either output reaches the goal, yet they do not describe the same solution. This is an accessible entry point to JUICE: it studies how image and text can be generated together while influencing one another along the way.

This October 20, 2026 preprint is by researchers at NYU, Harvard, UIUC, Princeton, and UPenn. Its value lies in the modeling choice and controlled experiments: unfinished image and text states can evolve together. It does not establish general visual reasoning or show that this process replaces natural-language chain of thought.

### Step 1: represent both modalities as continuously editable vectors

Text is commonly generated by choosing vocabulary tokens one at a time, while image generation can repeatedly revise a continuous state starting from noise. JUICE first passes both modalities through pretrained encoders. These produce representations: vectors whose values carry information about image regions or words in context.

The default uses SigLIP2 for images and Flan-T5-Small for text, yielding 256 image positions and 128 text positions. They inhabit separate continuous spaces and are projected before interacting; an image vector is not inherently a text vector. The encoders remain frozen during backbone training, so their pretrained knowledge is an important source of capability.

A newly trained Transformer, MM-RiT, predicts states in these spaces. Fixed decoders subsequently turn them into pixels and tokens. “No language-model initialization” refers to the MM-RiT backbone, not to an entire system without pretrained components.

### Step 2: use two progress values to specify what is given

The paper uses t for progress from noise to clean data: t=0 is pure noise and t=1 is a clean representation. During training, noise ε and a true representation z are mixed as z(t)=(1−t)ε+t·z. The network learns to predict clean z from this mixture. An intuitive view of flow matching is learning update directions that move noise toward a data-like representation over multiple steps.

JUICE assigns separate progress values to image and text. For text-to-image generation, text stays at t=1 while the image advances from 0 to 1; captioning reverses the roles. Joint generation starts both from noise. Visual question answering specifies this per position: the image and question stay fixed while answer positions are generated.

This explains the square in Figure 2. Its axes are the two progress values. Paths along an edge have one clean modality; paths through the interior generate both. Their schedules can differ, so the modalities need not become clear at the same rate.

### Step 3: each update uses both current states

Within MM-RiT, image and text first have separate Q, K, and V projections. Their sequences then participate in one bidirectional joint attention operation. Attention retrieves relevant information from other positions; bidirectionality lets image positions use text positions and vice versa. Each modality retains its own output projections and feedforward networks.

During coupled sampling, the model computes both update directions from the same current image–text state before updating either stream. The next step therefore sees both advanced states. This differs from completing the text before drawing, and from two independent generation processes.

The interacting objects are continuous vectors, not readable explanations emitted at every step. Decoding intermediate states helps inspect the process; it does not show that every update corresponds to a human-interpretable reasoning operation.

### Why conditional tasks alone are insufficient training

Training only with one complete modality and one generation target rarely exposes the model to two unfinished modalities. Joint generation repeatedly encounters exactly that condition. Default pretraining mixes 55.6% joint denoising, 22.2% text-to-image, and 22.2% image-to-text examples. Denoising loss applies to the current generation targets.

Training only on jointly noisy inputs is also insufficient: actual question answering and text-to-image inference have exactly clean conditions. Mixing these tasks covers the information conditions encountered during inference. Tasks that all sound like “generate image and text” can expose the network to substantially different states.

GenEval checks whether generated images satisfy requirements such as objects, counts, colors, and relative positions. At 668M backbone size, the mixed recipe obtains 48.41% GenEval, versus 36.30% for the two conditional directions alone and 31.33% for joint denoising alone. Data, backbone, and training schedule are shared. Further controls match supervised target counts or block cross-modal exchange, showing that additional targets do not fully explain the improvement. Each configuration is trained once, however, and the mixture is not established as optimal across scales.

### Back to the maze: converging on the same route

Keep the input maze and question fixed, and initialize the target solved image and target move sequence with noise. Early states may still accommodate multiple routes. Subsequent updates allow each stream to use the other’s evolving state. In two illustrated cases, the moves stabilize first and the image follows, or the image stabilizes first and the moves follow.

These are observations of intermediate states, not an explicit rule that the first stream to decide becomes authoritative. Two examples also do not prove a general planning algorithm. The narrower supported conclusion is that coordination can occur in either direction on these tasks without a predefined generation order.

### The decisive comparison matches backbone calls

The multiple-solution maze experiment adapts the 2.1B models for another 5,000 updates. Training uses 200,000 examples at 5×5, 6×6, and 7×7 grid sizes. Evaluation uses 500 unseen layouts, each with 2–16 shortest routes. Joint success requires two legal shortest routes that are the same route, rather than matching a unique stored reference.

Table 7 compares 16 backbone calls and averages two sampling seeds. For SigLIP2, independent sampling achieves 54.6% joint success, coupled sampling 93.7%, text-first sampling 85.3%, and image-first sampling 95.2%. Coupling removes many disagreements but does not outperform the best sequential baseline. Appendix D.2 also finds image-first significantly better than coupling for SigLIP2 in its paired test.

A coupled call updates both streams, giving 16 shared steps. Independent and sequential methods receive eight steps per stream. Encoder and decoder calls are excluded, so this does not establish equal end-to-end latency. Figure 11 uses a different illustrative budget: independent sampling gets 16 steps per stream, or 32 calls. Its pictures should not be read as the exact budget comparison in Table 7.

### What improves on general tasks, and what remains weak?

The final 2.1B variants generate 224×224 images. Text-to-image uses 25 Euler updates with guidance=5; DINO reaches 0.88 GenEval and SigLIP2 0.87. Visual question answering uses 16 steps with guidance=3; SigLIP2 reaches 73.1 on VQAv2 test-dev. Euler integration advances the state step by step. Guidance strengthens the condition’s effect using the difference between conditioned and reference predictions.

These scores do not imply broad superiority. The SigLIP2 variant scores 34.4 on AI2D and 29.6 on MMMU in Table 6, below several models initialized from pretrained language models. Longer descriptions can contain grammatical errors or invented words. In the 668M control, continuous text nearly matches autoregressive text on semantic image–caption CLIPScore but scores much lower on CIDEr, which measures agreement with reference phrasing. Semantic relevance and reliable wording deserve separate evaluation.

The claim that adding another ability preserves image generation is also conditional. At shared guidance, JUICE obtains 48.41% GenEval versus 47.86% for the text-to-image-only reference. With guidance tuned separately, that specialized model reaches 51.23%, exceeding JUICE. This is evidence about a particular design tradeoff, not a general guarantee that unification is free.

### A systems reading: 2.1B does not count the entire pipeline

Appendix A.5 distinguishes trainable backbone size from the complete pipeline. The large SigLIP2 backbone is about 2.12B parameters; loading the components needed for both directions brings the total to approximately 3.03B. Frozen components can still consume inference compute and memory, so deployment comparisons should not use only the abstract’s backbone count.

Quantitative question answering uses a parallel text decoder that reads all answer positions at once. Mazes use a separately trained linear task head. Some qualitative joint image–text samples use an autoregressive text decoder. These paths should remain distinct; not every displayed result uses the same fully parallel text readout.

The following is my systems inference: when both streams change each round and attention is bidirectional, autoregressive KV reuse assumptions based on an immutable generated prefix do not transfer directly. Actual implementations would need to identify reusable condition computations layer by layer. Backbone-call budgets also do not translate automatically into serving throughput or latency; this note does not present JUICE as a demonstrated inference speedup.

### How to read it efficiently

Worth a close read. Start with Figures 1–2 and Table 7 to understand two progress values and coordinated updates. Then read Sections 3.2–3.5, the training controls in Section 4.3, and scoring and budgets in Appendices D.1–D.2. Read Appendix A.4 afterward if continuous text generation and readout interest you.

Only three starting concepts are essential: representations encode content as vectors; attention lets positions retrieve information from other positions; noise-based generation forms outputs through repeated updates. The full mathematics of flow matching can wait. The useful questions are exactly where coupled and independent generation differ, why training must include two unfinished modalities, and why 93.7% is not a general visual-reasoning success rate.

## Optional reading · Reason Through the Latent! Making Latent Visual Reasoning Necessary

**Year / publication：** 2026 · arXiv 2026 · Korea University / AIGEN Sciences · first preprint 2026-09-06; v3 2026-09-11 · [Original source](<https://arxiv.org/abs/2609.06746v3>)

**Reading guidance：** Read Figure 2, Section 3, and Sections 5.1–5.3 closely. First separate initialization, recurrent updating, and answer decoding; then use Table 2 to test the contribution of each component. Focus on computational paths and interventions rather than leaderboard rank.

### Does solving a visual question mean the proposed reasoning was used?

Consider our teaching example: an image contains a red cup and a white cup, and the question asks whether the red cup is to the left of the white cup. A vision-language model converts the image and question into internal vectors before answering. Some methods add several rounds of vector computation so that the model can reconsider spatial relations without writing a textual reasoning trace. This is called latent reasoning. The hidden state is a numerical representation, not a concealed natural-language paragraph.

The answer decoder may still read the original visual information directly. It could answer correctly even if the added computation contributes nothing. The paper first replaces existing methods’ proposed latent states with blank-image states, states from different examples, or noise while retaining the original multimodal context. Some methods change little: UniVLR moves by no more than 0.5 percentage point across the three interventions. This supports weak dependence on the replaced content in that setting, not the conclusion that those methods are useless on every task. [Section 2 and Figure 1](https://arxiv.org/html/2609.06746v3#S2)

### Preserve what the pretrained model already saw before revisiting it

CVRR does not begin with an empty vector and relearn vision. It first lets the pretrained model process the image and question normally. After the lower layers, vectors at the question positions already incorporate visual information. The method extracts these vectors as the initial state h1 and separately retains visual-position vectors v for repeated access. Here h1 is a collection of vectors conditioned on both image and question, with positions still corresponding to pieces of question text, or tokens.

The insertion point is selected rather than arbitrary. Using training pairs with the same question but different images and answers, the authors swap visual activations at successive layers and measure the change in answer preference. They seek a region where question representations already carry visual competence while visual positions still influence the answer. For the main Qwen2.5-VL-7B experiments, the boundary follows layer 20. Layer 21 then runs once with its native parameters to form h1 and v. Evaluation benchmarks are not used to select this boundary. [Sections 3.1–3.2 and Appendix H](https://arxiv.org/html/2609.06746v3#S3)

### Keep reading the image during recurrence, then answer through its result

The model retains the same v, puts the latest question state back into its original positions, and executes the same adapted layer 21 again. Sharing parameters does not produce identical outputs because the question state changes. The default T=4 consists of one native initialization and three updates. Each update averages the previous state and the newly computed state. The cup example explains why revisiting evidence could help, but the paper does not label these updates as finding cups, identifying colors, and comparing positions.

Only after recurrence does CVRR remove visual rows and the original multimodal KV cache. A KV cache stores attention keys and values for subsequent generation; deleting explicit image tokens while retaining image-conditioned caches could leave another route. Lower layers therefore use caches produced from the text-only question, while the upper answer decoder receives the final state hT. Image-conditioned information must pass through hT to affect the answer, although recurrence can read v throughout its computation. [Sections 3.2–3.3 and Algorithm 1](https://arxiv.org/html/2609.06746v3#S3)

### Train a small adapter, and retrain the relevant controls

The backbone remains frozen. Only LoRA parameters on the shared recurrent layer are trained. LoRA introduces small trainable matrices that modify the original computation; this experiment trains approximately 2.88 million parameters, or 0.0348% of the total. The objective is answer-token cross-entropy: increase the probability of correct answer tokens. Although the dataset is named Visual CoT, CVRR does not require imitating teacher reasoning trajectories or specifying a correct target for each latent state.

Main training uses 438,000 Visual CoT question–answer pairs, four B200 180GB GPUs, a global batch size of 128, and three epochs, or three passes over the training data. Results come from one training run with seed 0. The authors also train an ordinary supervised-fine-tuning control retaining the full multimodal path and six latent reasoners compatible with the same no-bypass interface. The latter are retrained using common data and training settings while preserving their mechanisms and objectives; this is not simply deleting images from already-trained models and evaluating the damage. [Sections 4.1–4.2 and Appendix B](https://arxiv.org/html/2609.06746v3#S4)

### The central result is preserved competence with a required path

Start with the original backbone comparison rather than interpreting weak restricted baselines as universal superiority. CVRR scores 81.2% on V*, versus 79.6% for the backbone, and 52.7% MMVP pair accuracy, versus 47.3%. V* contains only 191 high-resolution visual questions. MMVP contains 300 questions over 150 similar-image pairs; pair accuracy requires both questions in a pair to be correct. BLINK overall accuracy moves only from 55.0% to 55.2%, while MME-RealWorld-Lite drops from 50.8% to 46.7%.

The comparison closer to the paper’s claim is that, after removing alternative visual routes and retraining, the six compatible baselines reach at most 39.8% on V*, while CVRR retains 81.2%. Requiring answers to pass through a latent state is therefore insufficient by itself; pretrained visual competence must enter that path. CVRR matches or exceeds ordinary supervised fine-tuning on V*, MMVP, and BLINK, but these results do not establish that the interface suits every visual task. [Table 1 and Section 4.3](https://arxiv.org/html/2609.06746v3#S4)

### How do we know recurrence is not merely forwarding an existing answer?

Even a required hT could simply forward information already in h1. Table 2 therefore removes components and retrains. Keeping native initialization and the learned transition but removing further access to v reduces V* from 81.2% to 69.1% and MMVP pair accuracy from 52.7% to 18.0%. Retaining visual access but removing the learned adaptation yields 76.4% and 32.7%. These comparisons support contributions from both persistent evidence access and learned updates.

The authors also cross the initial state from one image with visual evidence from its paired alternative. Clean evidence can pull an incorrect initial state toward the correct answer, and incorrect evidence can pull a correct state away. Blocking question-to-visual connections largely removes both effects. This supplies stronger evidence that newly accessed information changes subsequent computation than attention visualizations alone.

Another intervention keeps the question fixed and replaces the final state with one obtained from the alternative image. In our example, the question about cup positions stays the same while the internal result from another arrangement is substituted. The paper’s MMVP mechanistic analysis drops from 73.3% to 26.7%. This analysis primarily uses restricted first-option-token readout, so it must not be mixed with Table 1’s full-generation accuracy. It tests whether disrupted question content alone explains the failure and supports dependence on image-conditioned content. [Sections 5.1–5.3](https://arxiv.org/html/2609.06746v3#S5)

### A required path does not eliminate every shortcut

The interface removes visual routes around hT. It does not eliminate answer regularities in the data, language priors, or simple recognition results already present in h1. Depending on a vector also does not automatically establish human-interpretable multistep reasoning. The interventions and ablations strengthen the evidence, but they do not test every possible shortcut or demonstrate general visual competence in open environments. The method repeatedly reads fixed evidence rather than taking a new image or acquiring a new observation.

Appendix I also tests Gemma and InternVL backbones, so the evidence is not exclusive to Qwen. However, the boundary is localized separately for each backbone, and sensitivity to state replacement varies. Main mechanistic analyses focus on multiple-choice settings. Training uses a single seed; confidence intervals come from resampling evaluation examples and do not measure variation across training runs.

Additional computation is not free. On one B200 over 32 examples, with three timing runs and image preprocessing excluded, measured latency is 1.146 seconds for T=4 and 1.044 seconds for T=1. Configurations with T≥2 are independently trained, whereas T=1 has no trainable recurrent adapter. Accuracy is also nonmonotonic across larger depths. This is not evidence that a deployed checkpoint becomes reliably stronger just by running extra iterations. [Section 6 and Appendices B, D, and I](https://arxiv.org/html/2609.06746v3#S6)

### Reading route: draw the three stages and their available information

Begin with Figure 2 and draw normal multimodal initialization, shared-layer updating, and final answer decoding separately. Mark which vectors and caches each stage can access. Then inspect Table 2 and ask whether competence survives after removing a component and retraining. Finally, read Figure 4’s same-question state replacement to understand why the question itself must remain controlled. These three checks transfer to other latent-reasoning studies more readily than memorizing every score.

## Optional reading · Look Back, Think Ahead: Visual Memory on Demand for Efficient Multimodal Reasoning

**Year / publication：** 2026 · arXiv 2026 · CityU / Zhejiang / Peking / Nankai / Huawei · v1 2026-10-08 · [Original source](<https://arxiv.org/abs/2610.12060v1>)

**Reading guidance：** Read the cache and routing process in §3.1–3.3, then examine the accounting in §4.4 and Appendix C. The contribution is a trainable mechanism for accessing visual evidence.

### 1. Halfway through reasoning, a small label matters again

Consider a teaching example: a diagram contains a right triangle with perpendicular sides labeled 3 and 4, and asks for its area. The model first identifies the right angle, then reads the corresponding side labels, and finally computes 3×4÷2. It need not inspect the entire image repeatedly while multiplying. But if compression discarded the label 4 at the start, a longer textual explanation cannot recover that missing evidence.

ViMoD studies this changing demand: different stages of a response may need different image regions. Selecting a small, permanently fixed set of visual tokens once may fail to support later steps. The authors retain recoverable details and decide which ones should participate in computation as reasoning progresses. [§1 and Figures 1–2](https://arxiv.org/html/2610.12060v1)

### 2. Store the details, but read only part of them at each step

The model first fully processes the image and question to obtain KV caches: keys and values that subsequent attention computations can reuse. Fine KV denotes these original visual-token caches at each layer; Coarse KV is a smaller cache obtained by aggregating Fine entries. Coarse entries remain active, while selected Fine entries join them on demand. Unselected Fine entries remain stored, so recall does not require reconstructing pixels from a lossy summary. [§3.1 and Algorithm 1](https://arxiv.org/html/2610.12060v1)

A counting example clarifies the budget. With 90 original Fine tokens, the 9:1 configuration produces approximately ten Coarse tokens. A 20% target means about 18 active visual entries on average during generation, already including those ten summaries. A selection-threshold offset calibrates average usage. It does not impose exactly 18 entries at every step, and does not mean that only 20% of the original cache is stored. [Appendix C.2](https://arxiv.org/html/2610.12060v1)

### 3. DART learns groups that treat small labels differently from blank areas

DART constructs the summaries and groups. Starting from a regular grid, it learns both how many original tokens each group should contain and which tokens belong together; membership can cross the initial grid boundaries. The number of groups stays fixed, and every original token still belongs to one group. This allows coarser aggregation in blank areas and finer groups around text or a right-angle marker. [§3.2 and Figure 5](https://arxiv.org/html/2610.12060v1)

Each group provides a Coarse summary and an index back to its original Fine members. Layer-wise keys are pooled with learned weights, while values pass through a small encoder before pooling. Recall retrieves the group's original KV rather than enlarging its summary. Grouping therefore determines both compression quality and recall cost; a recalled group can also contain details that are not currently useful. [§3.2, Equations 4–5](https://arxiv.org/html/2610.12060v1)

### 4. TRACE uses the reasoning so far to decide where to look next

TRACE makes a routing decision every 16 generated tokens. It reads available hidden states—the backbone's internal representations of the current text—maintains summaries of history at different timescales through a small state-space module, and predicts the visual groups needed next. Intuitively, its internal state can track something like “the right angle has been established; next comes reading the side lengths.” At inference it uses only information already available, not future text. [§3.3 and Appendix B, Table 7](https://arxiv.org/html/2610.12060v1)

It also decides whether to retain the current groups or replace them with the proposed set. An update can add, remove, or clear details; Coarse summaries remain accessible even when the Fine set is empty. Attention at each layer jointly reads Coarse entries, active Fine entries, and text history, a combination called Joint-KV. Looking back means changing which cached entries participate in attention, rather than cropping the image and invoking the vision encoder again. [§3.3 and Appendix A.2](https://arxiv.org/html/2610.12060v1)

### 5. How these decisions are learned

The Qwen3-VL-4B-Instruct backbone stays frozen. DART is first trained on 57,420 task-verified response trajectories to make predictions under compression resemble predictions with full visual context. DART is then frozen, and Qwen3.8-27B annotates the evidence boxes needed for reasoning segments in 80,000 examples, supervising TRACE's group selection and update decisions. Only auxiliary modules are trained, totaling approximately 0.0546% of the backbone's parameters; this count excludes the annotation teacher. [§3.4 and Appendix B](https://arxiv.org/html/2610.12060v1)

Finally, 4,800 questions are selected from that supervised set, with 16 responses generated per question. Final-answer correctness trains TRACE further, while lower Fine occupancy is rewarded among correct responses to the same question. Teacher guidance on upcoming evidence remains part of training: the teacher sees the image, question, and generated student prefix, but neither the reference answer nor future student text. The additional cost feedback does not impose a hard accuracy or usage constraint. [Appendices A.3 and B.3](https://arxiv.org/html/2610.12060v1)

### 6. What the score of 80.33 actually means

Across eight reasoning benchmarks at a 20% target budget with 9:1 memory, ViMoD's mean normalized score is 80.33, versus 57.78 for DivPrune, the strongest evaluated one-shot method. Each benchmark score is divided by the corresponding uncompressed model's score under the same settings and multiplied by 100 before averaging. Thus 80.33 is not 80.33% answer accuracy. A control that applies DSTP's attention-change access rule to the same DART memory scores 72.96, providing a more targeted comparison of access policies. [Table 1 and §4.1](https://arxiv.org/html/2610.12060v1)

All methods use greedy decoding—choosing the highest-probability next token—with presence_penalty=0. The main MMMU-Pro table permits up to 4,096 generated tokens, and the uncompressed baseline scores 30.92%. The authors note a technical-report score of 53.2%, but do not isolate the effects of decoding settings, repetition, and truncation. These comparisons therefore support improvements within the shared experimental protocol, not direct comparisons with external leaderboards. [Appendix C.1](https://arxiv.org/html/2610.12060v1)

### 7. A faster complete run, with heavier startup and more memory

A separate efficiency experiment uses MMMU-Pro on one H200, batch size eight, and a maximum of 8,192 generated tokens. At a 40% target budget, ViMoD completes the evaluation run in 15.2–20.4% less time than FastV, VisionZip, and DivPrune. This is complete-run wall-clock time, not mean request latency or a service-level guarantee. Those baselines generate more tokens per second but produce 15.9–29.9% more tokens than the uncompressed model, offsetting per-step savings. [§4.4 and Appendix C.4](https://arxiv.org/html/2610.12060v1)

In this experiment, autoregressive decoding accounts for 94.4% of the uncompressed model's runtime, allowing long outputs to amortize initialization. ViMoD preserves full prefill and builds Coarse memory; at 20–50% target budgets, its mean time to first token is higher than that of the one-shot baselines. Peak GPU memory also rises from Full's 38.40 GiB to 42.67 GiB. These are total inference peaks, not KV-only measurements. Fewer entries participating in attention does not imply less memory occupied. [§4.4 and Appendix C.4](https://arxiv.org/html/2610.12060v1)

### 8. Questions to take away, and a reading route

Start with Figure 4 and Algorithm 1, distinguishing stored evidence from evidence currently being read. Then examine Table 1, Figure 6, and Appendix C's budget and timing definitions. Short answers, sustained demand for broad visual evidence, missed groups, or late updates can weaken the gains. Other backbones and decoding settings remain unverified. For systems work, the useful lesson is to measure answer quality, output length, first-token time, complete-run time, and peak memory together. [§5](https://arxiv.org/html/2610.12060v1)
