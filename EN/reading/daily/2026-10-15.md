# From request scheduling to RL rollouts: four foundational papers

Start with Orca; optionally explore PagedAttention, SGLang, and HybridFlow. Connect scheduling, KV memory, program execution, and training-generation transitions.

Each digest recommends 1 main paper and 2–4 optional papers. A recommendation does not mean it has been read, and there is no need to finish everything in one day. Build the foundations, then connect them to current agent serving and RL infrastructure work.

## Main reading · Orca: A Distributed Serving System for Transformer-Based Generative Models

- **Year / publication：** 2022 · OSDI 2022 · [Original source](<https://www.usenix.org/conference/osdi22/presentation/yu>)
- **Core contribution：** Schedules at generation-iteration boundaries so completed requests leave and waiting requests enter; selective batching handles different operators' batching needs.
- **Connection to current work：** Provides a baseline for agent scheduling and mixed-length rollouts: understand admission at a decode step before reasoning about cross-turn priority and KV residency.
- **Reading guidance：** Read closely. Spend about 25 minutes on the problem, scheduling design, and evaluation setup; draw a timeline for two long requests and one short request before inspecting implementation details.
- **Prerequisites：** Autoregressive token generation and the distinction between prefill and decode.
- **Limitations：** The evaluation reflects its original hardware and models. Iteration scheduling alone does not establish an optimal policy for multi-turn tool-using agents.

## Optional reading · Efficient Memory Management for Large Language Model Serving with PagedAttention

- **Year / publication：** 2023 · SOSP 2023 · [Original source](<https://arxiv.org/abs/2309.06180>)
- **Core contribution：** Maps logical KV blocks to physical blocks to reduce fragmentation and enable sharing and copy-on-write as sequences grow.
- **Connection to current work：** Explains why admission capacity depends on memory layout as well as compute, grounding later questions about prefix retention, eviction, and CPU offload.
- **Reading guidance：** Worth a close read, potentially next. Start with block tables, sharing, and copy-on-write; sketch two requests with a shared prefix before studying the attention kernel.
- **Prerequisites：** KV state grows with generated tokens; understand the dynamic-batching problem in Orca.
- **Limitations：** Paged allocation does not by itself choose which sessions to retain or how to handle tool waiting and cross-device migration.

## Optional reading · SGLang: Efficient Execution of Structured Language Model Programs

- **Year / publication：** 2024 · NeurIPS 2024 · [Original source](<https://proceedings.nips.cc/paper_files/paper/2024/hash/724be4472168f31ba1c9ac630f15dec8-Abstract-Conference.html>)
- **Core contribution：** Co-designs a language-program frontend and runtime, using RadixAttention for KV prefix reuse and optimizing structured generation.
- **Connection to current work：** Connects program structure with cache reuse, informing shared histories, branching, and prefix retention in multi-turn agents.
- **Reading guidance：** Read the RadixAttention and program-execution sections selectively. Draw a prefix tree for a tool-using conversation and identify reusable KV.
- **Prerequisites：** Prefix caching, trees, and the logical-versus-physical block distinction in PagedAttention.
- **Limitations：** This is the original design. Current SGLang has evolved, so distinguish the paper's mechanisms from today's implementation.

## Optional reading · HybridFlow: A Flexible and Efficient RLHF Framework

- **Year / publication：** 2025 · EuroSys 2025 · preprint 2024 · [Original source](<https://i.cs.hku.hk/~cwu/papers/gmsheng-eurosys25.pdf>)
- **Core contribution：** Combines single- and multi-controller execution and uses 3D-HybridEngine to reduce policy-model resharding costs between generation and training.
- **Connection to current work：** Directly relates to rollout workers, weight synchronization, and changes in parallelism; separates orchestration, data movement, and GPU execution costs.
- **Reading guidance：** Skim the dataflow now and read closely later. Draw GPU allocation and weight movement through generation, preparation, and training, then compare with a rollout pipeline.
- **Prerequisites：** An RLHF/GRPO loop, data parallelism, and tensor parallelism; use Ray, Megatron-LM, and ZeRO in the roadmap if needed.
- **Limitations：** The conference paper is from 2025 and the preprint from 2024. Original RLHF results do not directly establish performance for tool-heavy agent rollouts.
