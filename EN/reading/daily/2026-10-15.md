# Understanding the training–rollout boundary with HybridFlow

Read HybridFlow first; explore SGLang alongside current cache code, with Ray and DistServe for orchestration and resource scheduling. Orca and PagedAttention have already been read closely.

Each digest recommends 1 main paper and 2–4 optional papers. A recommendation does not mean it has been read, and there is no need to finish everything in one day. Build the foundations, then connect them to current agent serving and RL infrastructure work.

## Main reading · HybridFlow: A Flexible and Efficient RLHF Framework

- **Year / publication：** 2025 · EuroSys 2025 · preprint 2024 · [Original source](<https://i.cs.hku.hk/~cwu/papers/gmsheng-eurosys25.pdf>)
- **Core contribution：** Combines single- and multi-controller execution and uses 3D-HybridEngine to reduce policy-model resharding costs between generation and training.
- **Connection to current work：** Directly relates to rollout workers, weight synchronization, and changes in parallelism; separates orchestration, data movement, and GPU execution costs.
- **Reading guidance：** Main reading for this edition. Spend about 30 minutes mapping GPU allocation and weight movement across generation, preparation, and training, then read the controller design and 3D-HybridEngine; connect them to a familiar rollout/refit pipeline.
- **Prerequisites：** An RLHF/GRPO loop, data parallelism, and tensor parallelism; use Ray, Megatron-LM, and ZeRO in the roadmap if needed.
- **Limitations：** The conference paper is from 2025 and the preprint from 2024. Original RLHF results do not directly establish performance for tool-heavy agent rollouts.

## Optional reading · SGLang: Efficient Execution of Structured Language Model Programs

- **Year / publication：** 2024 · NeurIPS 2024 · [Original source](<https://proceedings.nips.cc/paper_files/paper/2024/hash/724be4472168f31ba1c9ac630f15dec8-Abstract-Conference.html>)
- **Core contribution：** Co-designs a language-program frontend and runtime, using RadixAttention for KV prefix reuse and optimizing structured generation.
- **Connection to current work：** Connects program structure with cache reuse, informing shared histories, branching, and prefix retention in multi-turn agents.
- **Reading guidance：** Read selectively with source pinned to commit f2b73d4, verified on 2026-10-15. Start with [registry.py](https://github.com/sgl-project/sglang/blob/f2b73d4f9b4e64415b8d775b0f811c7801f1728b/python/sglang/srt/mem_cache/registry.py#L83-L199) for UnifiedRadixCache component selection, then [SWA window coverage and independent eviction](https://github.com/sgl-project/sglang/blob/f2b73d4f9b4e64415b8d775b0f811c7801f1728b/python/sglang/srt/mem_cache/unified_cache/components/swa.py#L62-L100) and [Mamba recoverable state boundaries](https://github.com/sgl-project/sglang/blob/f2b73d4f9b4e64415b8d775b0f811c7801f1728b/python/sglang/srt/mem_cache/unified_cache/components/mamba.py#L147-L224). Trace prefix matching, insertion, eviction, and restoration.
- **Prerequisites：** Prefix caching, trees, and the logical-versus-physical block distinction in PagedAttention.
- **Limitations：** Separate the original paper from current code: ordinary full-attention can also use UnifiedRadixCache; SWA/Mamba components depend on the model. [HiCache](https://github.com/sgl-project/sglang/blob/f2b73d4f9b4e64415b8d775b0f811c7801f1728b/python/sglang/srt/mem_cache/hybrid_cache/hybrid_cache_controller.py#L203-L269) adds GPU/CPU/storage tiers, a separate dimension that can be combined with mixed model state.

## Optional reading · Ray: A Distributed Framework for Emerging AI Applications

- **Year / publication：** 2018 · OSDI 2018 · [Original source](<https://www.usenix.org/conference/osdi18/presentation/moritz>)
- **Core contribution：** Unifies tasks and actors in an execution engine with distributed scheduling and fault-tolerant control state for dynamic AI workloads.
- **Connection to current work：** Complements HybridFlow by separating control flow, worker state, object movement, and GPU resource scheduling.
- **Reading guidance：** Selectively read the task/actor model and scheduler. Explain why rollout workers often use persistent actors and where model state and large tensors should live.
- **Prerequisites：** Processes, remote calls, and stateful versus stateless tasks.
- **Limitations：** This describes the 2018 architecture; use it for abstractions and current official documentation for APIs and deployment.

## Optional reading · DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving

- **Year / publication：** 2024 · OSDI 2024 · [Original source](<https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin>)
- **Core contribution：** Separates prefill and decoding, selecting resources and parallelism for their distinct latency constraints to optimize goodput.
- **Connection to current work：** Builds on batching and paged KV memory to analyze stage isolation, KV transfer, and the different objectives of online serving and rollouts.
- **Reading guidance：** Worth a close read, possibly in a later edition. Distinguish throughput from goodput, then examine GPU allocation and transfer overhead.
- **Prerequisites：** Prefill/decode, TTFT/TPOT, continuous batching, and KV caches; Orca and PagedAttention provide the background.
- **Limitations：** Online-serving SLOs do not directly replace end-to-end trajectory completion objectives; gains depend on workload and interconnect conditions.
